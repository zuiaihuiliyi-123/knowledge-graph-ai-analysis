# 知识点自动标注设计（Scope C / P3）

> 交付物对应「试题自动挂知识点」。本文说明算法分层、数据模型、降级策略、接口、安全策略与**实测评测结果**。
> 实现位置：`backend/app/services/kp_labeler.py`（算法）、`backend/app/api/questions.py`（两个端点）、
> `backend/app/core/sql_database.py`（`t_question_embedding` / `t_kp_text` + DAO）、
> `frontend-vue/src/views/TeacherView.vue`（题目表单「自动标注」+「批量自动标注」）、
> 评测脚本 `backend/eval_kp_labeling.py`、测试 `backend/test_kp_labeler.py`。

---

## 一、目标与定位

老师出完题往往不挂知识点，导致「按知识点出题 / 覆盖率报表 / 推荐练题」全部失效。
本模块对题目自动产出**候选知识点**，教师一键采纳；批量模式可对整门课/整份文档跑建议。

**明确的边界**：自动标注只产出建议，**默认不写库**；写库必须显式 `apply=true` 且分数达阈值，
并且默认只补「尚未挂知识点」的题。**宁可少标，不可错标。**

**L2（2026-09-22）**：写库由「只写最高分的 1 个知识点」改为「**并入 top-k 个达阈值候选**」，
落 `t_question_kp` 关联表（论文 2.4.3 的一题多知识点口径）；语义是**合并而非覆盖**（见 §六 第 5 条）。

## 二、算法：三层证据 + 融合打分

| 层 | 证据 | 依赖 | 说明 |
|----|------|------|------|
| ① 字面匹配 lexical | 知识点名称出现在题干（权重 1.0）或选项/空位提示（0.7） | 知识点名称 | 名称越长越可信；**单字名称不参与**（噪音太大）；命中次数多小幅加成 |
| ② 向量召回 vector | 题目 embedding 与知识点 embedding 余弦相似度 | `EMBEDDING_API_KEY` | 余弦低于 `VEC_FLOOR=0.35` 视为无证据；线性拉伸到 [0,1] |
| ③ 图谱扩展 graph | 首轮候选沿 `PRECEDES`/`CONTAINS` **一跳**扩展 | Neo4j（或缓存/快照） | 只做「扩展」不做「新增」：邻居须已有直接证据才被加权；分值 = `GRAPH_DECAY(0.45) × 直接证据分` |

**融合公式（在可用证据层上做加权平均，缺失层不参与分母）**

```
score = Σ(wᵢ·sᵢ) / Σ(wᵢ)      for sᵢ > 0
w_lexical = 0.45, w_vector = 0.45, w_graph = 0.10
```

> 为什么是"可用层加权平均"而不是固定权重求和：后者会让"只有字面命中但命中很强（0.70）"的题
> 永远达不到写库阈值（0.60），向量层一旦不可用就整体失效。加权平均让分数语义变成
> **"在现有证据下的可信程度"**，与阈值口径一致（实测修正见开发记录）。

**阈值分两档**
- 有字面/向量**直接证据**：门槛 `MIN_SCORE = 0.30`；
- **仅由图谱扩展**得到的候选：门槛 `GRAPH_MIN_SCORE = 0.01`，标注 `graph_only=True`，
  只作为低置信建议展示，**禁止自动写库**；调用方收紧阈值（`min_score > 0.30`）时一并过滤。

**置信度**：`score ≥ 0.75` 高 / `≥ 0.50` 中 / 否则低（前端用颜色区分）。

## 三、数据模型（两张新表，`CREATE TABLE IF NOT EXISTS`，无需重建）

```sql
-- 题目向量（题干+选项；text_hash 用于判断题面是否变更，变了才重算）
t_question_embedding(question_id PK, course_id, document_id, text_hash, embedding(JSON), updated_at)

-- 知识点文本缓存（图谱不可用时的降级数据源；每次从图谱取数成功后覆盖写入）
t_kp_text(course_id, kp_id, document_id, name, category, description, updated_at, PK(course_id, kp_id))
```
两者都**无外键**，因此在 `delete_course` / 文档删除路径上显式清理（沿用项目"不留孤儿数据"的纪律）。

## 四、候选来源与降级矩阵

候选来源优先级：**Neo4j 图谱 → 本地缓存 `t_kp_text` → 外部注入（评测/测试）**。

| 图谱 | EMBEDDING_API_KEY | 可用能力 | meta 标记 |
|:----:|:----------------:|----------|-----------|
| 有 | 有 | 三层全开（最佳） | `graph_available=true, vector_available=true` |
| 有 | 无 | 字面 + 图谱扩展 | `vector_available=false`（`embedding_configured=false`） |
| 无 | 有 | 向量（名称来自缓存） | `catalog_source="cache"` |
| 无 | 无 | 仅有缓存时的字面匹配 | `catalog_source="cache"`，无缓存则 `"none"` + `reason` |

**任何一路不可用都不抛异常**，只把降级事实写进 `meta`，前端原样展示（避免"没结果却不知道为什么"）。

## 五、接口与前端入口

| 方法与路径 | 说明 |
|-----------|------|
| `POST /api/v1/questions/{id}/kp-candidates` | 单题候选（`top_k` 默认 5）；返回 `candidates[{kp_id,name,category,score,confidence,graph_only,sources,in_catalog}]` + `meta` |
| `POST /api/v1/questions/auto-label` | 批量：`course_id`（必填）、`document_id`、`question_ids`、`only_missing`（默认 true）、`apply`（默认 false）、`top_k`、`apply_threshold`（默认 0.6） |

权限：接口层 `require_teacher`，服务层再做课程归属校验（越权 4003；文档不属于该课程 2002）。

前端（教师端「题库管理」）：
1. 题目表单「关联知识点」旁 **自动标注** 按钮 → 候选弹窗（名称/类别/分数/置信度/**依据层**/仅关系推断），点「采纳」填入表单，**保存后**才写库；
2. 题库工具栏 **批量自动标注** 按钮 → 参数（文档、每题候选数、写入阈值、是否只处理未挂题）→「仅预览（不写库）」与「预览并写入达阈值项」两个动作，结果表格给出每题的最佳建议与写入状态。

## 六、安全策略（写库的 6 道闸门）

1. `apply` 默认 `False`：默认只出建议；
2. `only_missing=True` 默认：**不覆盖**教师已挂的知识点；
3. `score ≥ apply_threshold`（默认 0.60，高于入候选阈值 0.30）；
4. `in_catalog=True` 且 `graph_only=False`：候选必须存在于本课程知识点清单（避免写出悬空 kp_id，与新建题目 `4002` 同口径），纯关系推断的候选一律不写；
5. **并入而非覆盖（L2）**：写库是**合并**语义——该题已有的知识点与其主知识点**一律保留**，只新增尚不存在的候选。因此自动标注不会毁掉教师手工维护的多知识点集合，也不会夺走主知识点；
6. **数量上限（L2）**：单题最多并入 `top_k` 个候选，且合并后总数不超过 `MAX_KP_PER_QUESTION = 10`。

**L2 变更（2026-09-22）——写库口径**

| 项 | 变更 |
|---|---|
| 写入目标 | 由「只写最高分的 1 个 `kp_id`」→ **并入 top-k 个达阈值候选**，落 `t_question_kp` 关联表 |
| 语义 | **merge**：已有知识点与主知识点一律保留，只新增；默认 `only_missing=True` 时合并与覆盖**等价，行为不变** |
| 来源标记 | 新增行标 `source='AI'`；既有行**沿用原来源**（教师手工挂的仍是 `MANUAL`），便于区分「谁标的」 |
| 响应新增 | `applied_kp_ids`（本次新增的全部知识点）、`applied_kp_count`（新增关联行数）、`apply_mode="merge"` |

> 实测（course 65）：一次 `apply=True` 把多标签题从 **0 道**提升到 **29 道**（新增 31 行关联），
> 且教师手工标注的来源与主知识点均未被改动。详见 [题库与推荐系统设计.md](题库与推荐系统设计.md) §13.5。

## 七、评测（`backend/eval_kp_labeling.py`）

两种模式、均只读：

**模式 A｜真实留一评估（需 Neo4j）**
```bash
python eval_kp_labeling.py --course-id 65 --document-id 101
```
把已挂 `kp_id` 的题当作弱标签，隐藏后预测 top-k，输出 hit@1/3/5、MRR、无候选题数、耗时。
**这是评价标注准确率的主指标，需在有图库的环境执行。**

**模式 B｜离线自洽评估（无需 Neo4j / 无需 key）**
```bash
python eval_kp_labeling.py --snapshot eval_data/gold_第7章_树.json --synthetic
python eval_kp_labeling.py --snapshot backup/neo4j_20260905_145113.json --course-id 5 --synthetic
```
把每个知识点的 `description` 当作查询文本，评估「描述 → 该知识点」的命中情况（向量路自动关闭）。
支持两种输入格式：Neo4j JSON 备份、Gold 标注文件（`entities`/`relations`）。

**实测结果 1（旧：无 Neo4j、无 `EMBEDDING_API_KEY`，向量层关闭 —— 保留以对照）**

| 数据集 | 知识点数 | hit@1 | hit@3 | hit@5 | MRR | 图谱层命中 |
|--------|:------:|:-----:|:-----:|:-----:|:---:|:--------:|
| Gold《第7章 树》 | 49 | **0.102** | 0.204 | **0.469** | 0.200 | 12 |
| Neo4j 备份 course 5 | 69 | 0.0145 | 0.101 | 0.130 | 0.057 | 6 |

**结论（重要且诚实）**：
1. 关闭向量层后，标注**完全由「名称字面命中」驱动**——只有当文本里出现知识点名称时才可能命中；
   而知识点描述通常描述的是**父概念**（例如「栈」的描述里含"线性表"），因此"描述→自身"的自洽指标天然偏低；
2. 图谱扩展能显著把目标推进 top-5（Gold 集 46.9%），说明关系层确有贡献，但**不足以替代向量层**；
3. 真实场景（题干通常直接点名概念）应优于上述自洽指标，**需在有图库+有 key 的环境跑模式 A 才能给出可信准确率**；
4. 若要让自动标注在真实题库上可用，**配置 `EMBEDDING_API_KEY`（SiliconFlow bge-m3）是第一优先级**。

**实测结果 2（已配置 key，向量路 A/B —— course 65，121 题留一，弱标签）**

| 指标 | 关向量 | **开向量** | 增益 |
|------|:------:|:----------:|:----:|
| **hit@1** | 0.4667 | **0.7000** | **+0.2333** |
| hit@3 | 0.8000 | **0.8833** | +0.0833 |
| hit@5 | **0.9917** | 0.9083 | **−0.0834** ⚠️ |
| **MRR** | 0.6549 | **0.7883** | +0.1334 |
| 无候选的题数 | 0 | **0** | — |

`hit_layer_breakdown = {lexical: 109, vector: 109, graph: 0}` —— 字面与向量**各贡献 109 题**
（`graph: 0` 是本机图谱为空所致）；评测耗时 **0.47s**（向量从库批量读回，**零 API 调用**）。

> **上面第 4 条结论已被实测证实**：向量路让 hit@1 从 0.467 提到 **0.700**、MRR 0.655 → **0.788**。
> ⚠️ 唯一变差的是 `hit@5`（0.9917 → 0.9083）：向量路候选网更宽，把部分「纯字面就能进 top-5」
> 的真值挤到了第 6 位之后。真实写库只取 top-3 且要求 `score ≥ 0.6`，故 `hit@1/@3` 才是操作性指标。
>
> 三处静默修复（详见 [题库与推荐系统设计.md](题库与推荐系统设计.md) §13.9）：
> ① `label_question` 逐题重算 embedding → 改为复用已入库向量（省掉 121 次多余 API 调用）；
> ② `eval_course()` 原先不传 `embedder/kp_vectors`，**向量路恒关** —— 这才使旧报告的指标被低估；
> ③ **`question_text()` 丢失选项**（`options` 在 DB 原始行里是 JSON **字符串**，而代码只认 list）
> 　 → 字面层的「选项命中」（`OPTION_WEIGHT=0.7`）**从未生效**、向量只嵌入题干、
> 　 且 `text_hash` 不含选项（**改选项不触发重算向量**）。修复后有候选的题数 **80 → 120**、
> 　 多标签题 **51 → 73**。
> 　 ⚠️ **存量数据注意**：该修复改变了 `text_hash` 口径，**旧库里的题目向量只含题干**
> 　 （本机已重算 80/121 条含选项的向量）；对老库应重跑一次 `label_questions` 刷新向量。
>
> ⚠️ 该评测的真值来自历史挂载（**弱标签**），且已核查**主知识点中 0 道来自 AI 标注**（无自证）。

## 八、已知边界与后续

1. **向量层当前未启用**（本机无 key）：配置 key 后 `ensure_question_vectors` 会懒构建题目向量
   （题面变更才重算），向量路自动生效，无需改代码。
2. **知识点文本缓存需刷新**：缓存只在"图谱查询成功"时覆盖写入；图谱长期不可用期间新建的知识点不会进缓存。
3. **不做 LLM 复核**：第四层（把候选交给 LLM 在候选集内精选）未实现——候选集已经很小，
   收益有限而成本与不确定性高；如后续需要，接口位置已预留（`label_question` 之后追加即可）。
4. **关系扩展只做一跳**：两跳会显著增加误报，暂不引入。
5. **填空题的提示词（hint）参与匹配**：副作用是 hint 里若出现别的知识点名称会产生候选，属预期（教师可忽略）。

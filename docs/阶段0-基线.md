## 5. 阶段 0 都改了什么

| 改动 | 文件 | 为什么 |
|---|---|---|
| 库移出仓库：`SQLITE_DB_PATH=../../kg-data/app.db` | `backend/.env`（不入库）、`backend/.env.example` | 历史提交跟踪过 `backend/data/app.db`，`git switch/checkout` 会**静默覆盖**被忽略的同名文件 —— 2026-10-31 已因此丢失过一次本地库 |
| 启动前自动备份 + 轮转 | `backend/app/core/sql_database.py`（`auto_backup()` / `_rotate_auto_backups()`）、`backend/app/main.py`（`lifespan` 内 `init_tables()` 之前）、`backend/app/core/config.py`（`AUTO_BACKUP` / `AUTO_BACKUP_KEEP` / `BACKUP_DIR`） | 迁移本身是写操作；「最近一次启动前的快照」是唯一既新鲜又廉价可得的回退点 |
| 事故记录 | `docs/问题修复记录.md` 第 7 条 | 该文件专门收集「真实缺陷 + 定位 + 修复 + 验证」 |

验证：

- 连续调用 `auto_backup()` 12 次 → 目录内恒为 10 份，每份可独立打开（17 表 / 11 课 / 130 题）
- `AUTO_BACKUP=0` → 不再产生新备份；库不存在或 0 字节 → 跳过且不创建文件
- `ruff check .` 通过；`import app.main` 通过

# 知识抽取准确率测试报告（六文档 · v1.8 原 Prompt 复测）

> **结论先行**：本报告用**未做任何 Prompt 修改的 v1.8 原版抽取器**，对 6 篇真实课程章节、3 门课程、169,438 字符、279 个金标准实体 / 293 条金标准关系做了 **5 轮独立 API 抽取**。
>
> - **六篇整体**：关系主指标 F1 均值 **0.7168**，pooled F1 **0.7635**，均高于 70%；
> - **逐篇看**：D1–D4 四篇为 0.8909 / 0.9090 / 0.8477 / 0.9141，全部 ≥70%；**D5 / D6 两篇为 0.3625 / 0.3769，未达标**；
> - **人工抽样**：关系 94/100 = **94.0%**（95% CI [87.5%, 97.2%]），实体 45/50 = **90.0%**（95% CI [78.6%, 95.7%]）；
> - **PDF 独立验证**：17,380 字符，抽取 45 实体 / 23 关系，人工全量复核 17/23 = **73.9%**（95% CI [53.5%, 87.5%]）。
>
> **必须明确的口径**：v1.8 的“六篇整体”达标，但“六篇逐篇”不是 6/6 达标——D5/D6 暴露了**跨章节泛化不足**。本报告不把整体均值包装成“每篇都过 70%”。作为对照，v1.9.1 的本体扩展版本可把 D5/D6 提升到 0.7641 / 0.7525，但 D5/D6 因此变成开发集，详见第 6 节。

## 2. 抽取链路、口径与冻结参数

### 2.1 真实链路

```
TXT / PDF
  → DocumentParser
  → chunk_text_for_llm（chunk=6000 tokens，overlap=400 tokens）
  → KnowledgeExtractor（DeepSeek deepseek-chat，并发 4，Prompt v1.8）
  → _merge_results（按名去重、类型白名单、悬空端点过滤、置信度阈值）
  → pred_*.json 落盘
  → eval_accuracy.py 离线评分
```

运行前设置 `EXTRACT_CACHE=0`，确保每轮都是真实 API 调用。

### 2.2 指标

- 实体：名称精确匹配，匹配前经冻结归一化（n1）。
- 关系：`(source, rel_type, target)` 三元组，方向必须一致。
- 主指标 `relation_primary`：Precision 用 Full 集，Recall 用 Core 集，F1 = 2PR/(P+R)。
- 同时报告 `F1_core`、`F1_full`、按类型 P/R/F1、Macro-F1、方向错误率、错误五分类、对账等式。
- 人工抽样：Precision + Wilson 95% CI；召回由自动评测给出。

### 2.3 冻结参数

| 参数 | 值 |
|---|---|
| Prompt 版本 | **v1.8（原版，未修改）** |
| 模型 | `deepseek-chat` |
| temperature | 0.3 |
| chunk / overlap | 6000 / 400 tokens |
| max_output_tokens | 8192 |
| 抽取并发 | 4 |
| 轮次 | 5 轮独立 |
| 抽取缓存 | 关闭（`EXTRACT_CACHE=0`） |
| 归一化版本 | n1 |
| 评测日期 | 2026-11-14 |

## 4. 误差分析

### 4.1 错误五分类（5 轮合计）

| 类别 | 5 轮合计 | 单轮均值 | 说明 |
|---|---:|---:|---|
| ① 臆造（节点对不在 Full） | 61 | 12.2 | 主要是 D5/D6 的弱关联与错误挂载 |
| ② 方向颠倒 | 7 | 1.4 | D5 的“定量分析 ↔ 滴定分析”等 |
| ③ 类型混淆 | 7 | 1.4 | 把 PRECEDES/APPLIES_TO 写成 RELATED_TO/CONTAINS |
| ④ 同义拆分 | 0 | 0 | 归一化与去重生效 |
| ⑤ 完全漏抽（Core） | 57 | 11.4 | D5/D6 的 PRECEDES 与 APPLIES_TO 漏抽最多 |
| 评分前丢弃：重复三元组 | 205 | 41.0 | 跨 chunk overlap 的工程去重 |
| 评分前丢弃：低置信度 | 0 | 0 | 本阈值下未触发 |

**对账**：5 轮原始输出 506 条 = 计分 293 条 + 评分前丢弃 213 条；每篇每轮 `原始 = 计分 + 丢弃` 均成立。

### 4.2 D5 的典型错误（0.3625）

- **方向反**：`滴定分析 CONTAINS 定量分析`（应为 `定量分析 CONTAINS 滴定分析`）；
- **类型错**：`化学方程式 CONTAINS 反应物/系数`（组成成分，不是子类）；`酸碱反应 CONTAINS 酸`（酸是反应物，不是反应类型）；
- **弱关联**：`重量分析 RELATED_TO 百分产率`（原文分别讨论，未给直接关联）；
- **漏抽**：`物质守恒定律 PRECEDES 配平化学方程式`、`分子方程式 PRECEDES 完全离子方程式`、`半反应法 APPLIES_TO 氧化还原反应` 等没有稳定输出。

### 4.3 D6 的典型错误（0.3769）

- **APPLIES_TO 缺失**：`密度公式 APPLIES_TO 密度`、`温度换算公式 APPLIES_TO 三种温标`、`舍入规则 APPLIES_TO 有效数字` 被写成 RELATED_TO 或漏掉；
- **PRECEDES 缺失**：`假说 PRECEDES 科学理论` 等；
- **实体粒度/命名**：`平均质量`（应为 `平均原子质量`）、`初始化二叉树`、`更新节点高度`、`左子节点`、`平衡性` 等被当成独立知识点；
- **挂载点分歧**：`SI基本单位`、`科学方法`、`物质分类` 等关系的父节点不稳定。

### 4.4 D1–D4 的残余误差

D1–D4 的 20 轮全部 ≥0.81，剩余误差主要来自：

- 金标准的选择性标注（Gold 未收录但语义合理的关系被算 FP）；
- 跨 chunk 重复（D3 单轮原始关系最多，去重后稳定）；
- 少量方向/粒度差异（如物理的 APPLIES_TO 漏抽）。

## 6. 与 v1.9.1 本体扩展版对照

| 文档 | v1.8（原 Prompt，5 轮） | v1.9.1（加化学通用规则，5 轮） | 变化 |
|---|---:|---:|---:|
| D1 树 | 0.8909 | 0.8318 | -0.0591 |
| D2 复杂度 | 0.9090 | 0.8829 | -0.0261 |
| D3 物理运动学 | 0.8477 | 0.8305 | -0.0172 |
| D4 化学第 2 章 | 0.9141 | 0.8962 | -0.0179 |
| D5 化学第 4 章 | **0.3625** | **0.7641** | **+0.4016** |
| D6 化学第 1 章 | **0.3769** | **0.7525** | **+0.3756** |
| **六篇均值** | **0.7168** | **0.8263** | **+0.1095** |
| **pooled F1** | **0.7635** | **0.8296** | **+0.0661** |

**解读**：

- v1.9.1 的化学通用规则**显著修复了 D5/D6**（+0.40 / +0.38），代价是 D1–D4 各下降约 0.02–0.06（采样波动 + Prompt 变长后的无关扰动）；
- v1.9.1 让“6 篇逐篇全部 ≥70%”成立，但 D5/D6 是**参考过其错误模式后加入规则**的，因此它们是开发集分数，不是无偏泛化；
- v1.8 没有针对 D5/D6 调过 Prompt，因此它是**更干净的无偏基线**，但逐篇有 2 篇不达标。

**建议表述**：

## 9. 评委可能提问与回答（v1.8 专项）

### Q1：六篇均值 0.7168 过了 70%，是不是可以说 6 篇都达标？

**不能。** 逐篇是 D1–D4 达标、D5/D6 不达标（0.3625 / 0.3769）。0.7168 是六篇平均，被四篇高分拉过线。正确的说法是：“整体指标达标，但逐篇 2 篇未达标，跨章节泛化是主要缺口。”

### Q2：D5/D6 为什么这么低？

v1.8 的化学本体规则**只覆盖第 2 章**（元素周期表、离子、化学键、命名法）。第 4 章的 PRECEDES（方程式先后）、APPLIES_TO（公式/方法 → 对象）和第 1 章的测量/有效数字/温标规则不在 Prompt 里，模型只能用通用决策树猜，结果大量写成 RELATED_TO/CONTAINS，并有方向错误。按类型看，APPLIES_TO 0.5333、PRECEDES 0.4444，正好对应这个缺口。

### Q3：人工抽样 94%，为什么 D5 自动 F1 只有 0.36？是不是抽样放水？

不是。人工抽样是**整体 100 条**，其中 D1–D4 占 68 条且全对，D5 占 22 条（16 对 6 错），D6 只占 10 条。整体 94% 被 D1–D4 拉动，不能代表 D5/D6。自动 F1 同时惩罚漏抽，D5/D6 的漏抽（PRECEDES/APPLIES_TO）在人工抽样里抽不到，所以两个数字不矛盾。报告第 5.4 节把分章抽样列出来了。

### Q4：为什么 D6 人工抽样 10/10，自动 F1 却只有 0.38？

D6 只抽到 10 条，样本太小，恰好没抽到错误条目；自动评测覆盖全部 40 条 Gold 关系，能看见漏抽和错误类型。**不能因为 10/10 就认为 D6 没问题**，报告已明确写出这一点。

### Q5：v1.9.1 能把 D5/D6 拉到 0.76，为什么不用它作为主结果？

v1.9.1 是针对 D5/D6 的错误模式**新增化学通用规则**后的版本，D5/D6 因此变成开发集，不再是“未见过章节”的无偏测试。它可以作为“方法迭代有效”的证据，但不能替代 v1.8 的无偏基线。本报告把两者并列：v1.8 是原 Prompt 的真实水平，v1.9.1 是本体扩展后的开发集水平。

### Q6：按关系类型只有 CONTAINS 过 70%，是否说明系统整体不合格？

如果赛题按“所有关系类型都 ≥70%”判定，v1.8 确实不合格；如果按“整体准确率 ≥70%”判定，v1.8 的整体均值 0.7168 / pooled 0.7635 达标。赛题原文是“知识抽取的准确率不低于 70%”，通常按整体口径；但我们在报告里主动披露了按类型的短板，避免只报有利口径。

### Q7：PDF 17/23 = 73.9% 能不能说明泛化能力？

只能作为**格式链路验证**。23 条样本太少，CI 下界 53.5%，不能断言稳定 ≥70%。它的价值是证明 PDF 解析 → 抽取链路能跑通，并给出一个点估计；不是主要泛化证据。

### Q8：为什么 D5/D6 的实体 F1（0.85/0.77）比关系 F1（0.36/0.38）高这么多？

模型能抽出大部分知识点，但**关系类型和方向**判不准。知识图谱的核心价值在关系，所以关系 F1 是主指标；实体 F1 高不代表图谱可用。我们把两者都报，避免用实体高分掩盖关系短板。

### Q9：5 轮是不是在刷分？

不是。5 轮全部保留，D5/D6 的 10 轮全部低于 0.47；如果只挑最好一轮，D6 也只有 0.4674。5 轮均值 + 标准差 + 逐轮值是为了量化波动，不是为了挑数。

### Q10：如果比赛要求 6 篇都必须 ≥70%，怎么办？

两条路：① 用 v1.9.1 的本体扩展，但必须声明 D5/D6 是开发集；② 保留 v1.8 原 Prompt，如实报告 4/6 达标，并给出改进路线（补第 1/4 章本体、增加 PRECEDES/APPLIES_TO 正反例、人工审核入口）。不能通过修改 Gold 或挑轮次把 0.36 改成 0.70。

## 10. 结论

1. **v1.8 原 Prompt 在 6 篇 / 3 门课 / 169,438 字符 / 293 条关系上，整体关系 F1 均值 0.7168、pooled 0.7635，整体过 70%；人工抽样关系 94.0%（CI 下界 87.5%）、实体 90.0%（CI 下界 78.6%）也过 70%。**
2. **逐篇不是 6/6 达标**：D1–D4 为 0.8477–0.9141，D5/D6 为 0.3625/0.3769；按关系类型只有 CONTAINS 过 70%。报告如实披露，不把整体均值包装成逐篇达标。
3. **短板定位清楚**：v1.8 的化学本体只覆盖第 2 章，第 1/4 章的 PRECEDES / APPLIES_TO / 关系挂载是主要缺口；此外有实体粒度（初始化二叉树、左子节点、平衡性）和方向错误（滴定分析 ↔ 定量分析）。
4. **v1.9.1 本体扩展可把 D5/D6 提升到 0.7641/0.7525、六篇逐篇全部 ≥70%，但 D5/D6 因此成为开发集**；它是方法迭代有效的证据，不是无偏泛化证明。
5. **PDF 格式链路可用**，但 23 条样本的 73.9% 只能作为探索性验证，CI 下界 53.5%，不足以下强结论。

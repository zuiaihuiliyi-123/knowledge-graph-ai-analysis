# 题库功能说明（教师组题 + 学生练题）

> 交付物对应「教师端题库管理」与「学生端做题练习」。本文说明题型范围、判分口径、答案下发时机、作用域规则，以及与图谱/学习路径的联动方式。
> 实现位置：`backend/app/services/question_service.py`（业务）、`backend/app/api/questions.py`（教师端）、`backend/app/api/practice.py`（学生端）、`frontend-vue/src/views/TeacherView.vue`（题库管理 Tab）、`frontend-vue/src/views/StudentView.vue`（做题练习 Tab）。
> 推荐系统（召回 / 精排 / 组卷）的分层设计与后续改造计划见 [题库与推荐系统设计.md](题库与推荐系统设计.md)。

## 一、题型范围（Scope B）

| 题型 | 代码 | 判分方式 | 存储 |
|------|------|----------|------|
| 单选题 | `SINGLE` | 选项键归一化后严格相等（提交即判） | `options` = `[{key,text}]` JSON；`answer` = `"A"` |
| 多选题 | `MULTI` | 选项键**集合**严格相等（顺序无关，少选/多选均判错） | `answer` = `["A","C"]` |
| 判断题 | `JUDGE` | 布尔归一化后相等（`对/正确/是/true/T/1` 等价） | `answer` = `"true"` / `"false"` |
| **填空题** | `FILL` | **不自动判分**：提交只落库，由教师批改 | `options` = `[{key,label,hint,score,answer}]`（每空参考答案）；`answer` = 参考答案数组 |
| **解答题** | `ESSAY` | **不自动判分**：提交只落库，由教师批改 | `options` = `[]`；`answer` = 参考答案正文 |

- 主观题（填空/解答）**建题必须填参考答案**（填空题逐空填），这是教师批改的依据。
- 提交后写入 `grade_status='PENDING'`（未批改不判分、不计正确率、不进错题本、不进掌握度），教师批改后置 `GRADED` 并给出 0~100 分（`>=60` 记为答对）。
- **自动组卷/智能推荐默认不插入主观题**（不参与题型均衡与配额补齐），只有显式指定 `q_type=FILL/ESSAY` 时才出现。
- 完整口径、迁移方案与接口清单见 [主观题与批改设计.md](主观题与批改设计.md)。

`options` / `answer` 一律以 **JSON 文本**入库（`json.dumps` 序列化），理由：SQLite 无数组类型；且若对字符串直接原样入库，单选答案 `"A"` 回读时 `json.loads` 会失败、判断答案 `"true"` 会被误读成布尔值，导致「单选题永远判错」——该缺陷在开发期被 `test_question_bank.py` 捕获并修复（见 `SQLDatabase._json_text` 注释）。

## 二、防泄题：答案解析的下发时机

```
出题 GET /api/v1/practice/questions
    └── 走 _public_view() 白名单投影
        → 只返回 question_id / q_type / q_type_label / stem / options / difficulty / kp_id / is_favorited
        → 绝不包含 answer / analysis

提交 POST /api/v1/practice/submit
    └── 服务端判分 → 写 t_answer_record → 才返回 {is_correct, score, correct_answer, analysis}
```

- 出题与「我的收藏」列表都走同一白名单函数，避免新增端点时漏删字段。
- 学生答题记录接口（本人已作答）会返回正确答案，用于回看复习，属预期行为。
- 教师端（`/api/v1/questions`）返回完整答案与解析，且每个方法都做「课程归属校验」（非本课程教师 → `code 4003`）。

## 三、题目作用域

| 字段 | 必填 | 说明 |
|------|:----:|------|
| `course_id` | ✅ | 题目归属课程，三端统一整数 |
| `document_id` | ⬜ | 留空 = **课程通用题**；填写 = 挂到具体文档（校验该文档属于该课程） |
| `kp_id` | ⬜ | 逻辑外键 → Neo4j `KnowledgePoint`，用于「推荐知识点 → 直接练题」 |

出题查询规则：`WHERE course_id = ? AND is_active = 1 AND (document_id = ? OR document_id IS NULL)`
—— 即「本学习资料」范围会同时取到该文档题与课程通用题；选择「整门课程」则不再限制文档。

**文档删除**只清理该文档精确挂载的题目与作答记录，**课程通用题刻意保留**（`delete_questions_by_document` 仅匹配 `document_id = ?`）。

## 六、与既有模块的联动与边界

1. **与学习记录**：答题**不自动**写入 `t_learning_record`（避免"刷题"污染学习进度口径与既有测试报告数据）。学生如需标记掌握，请在图谱浏览/详情中使用「标记已掌握」。
2. **与图谱**：题目通过 `kp_id` 关联知识点；题目本身不写入 Neo4j，图模型零改动。
3. **与学习路径**：学生端「按推荐知识点出题」读取推荐结果；教师端教学监测仍按课程级汇总（未把刷题数据混入进度统计）。
4. **与选课体系**：系统当前无选课关系表，学生可见课程内全部启用题目（与文档、图谱的可见性口径一致）。若后续引入班级/选课，只需收紧 `PracticeService.get_questions` 的课程可见性判断。

## 八、已知限制

1. 不支持填空题 / 简答题（见第一节）。
2. 判断题/选择题仅按选项键判分，尚未支持「选项内容级」同义匹配。
3. 教师端暂不支持批量导入（Excel/CSV）与「AI 自动出题」（表已预留 `source` 字段：`MANUAL / AI / IMPORT`）。
4. 错题本口径为「曾经答错即保留」，不随答对自动移除（便于复习巩固；如需自动移除，可在 `PracticeService.wrong_book` 增加"最近一次作答为正确则跳过"的判定）。

## 九、演示数据填充脚本（`backend/seed_practice_data.py`）

**为什么需要**：冷启动阶段题库数据量不足 —— 实测 `backend/data/app.db` 里 `t_question` 仅 6 道题（全在课程 63）、`t_answer_record` 为 0 条、课程 63 只有 1 名学生有学习行为。此时「掌握度」「遗忘曲线」「题目推荐」等能力全部无法体现，属于空跑。该脚本负责把演示数据补齐。

### 9.1 题目怎么造（不依赖 LLM，答案可验证）

题目全部由图谱事实（`name` / `description` / `category`）构造，五类模板：

| # | 题型 | 模板 | 答案依据 |
|---|------|------|----------|
| 1 | SINGLE | 给出描述，问它是哪个知识点 | 该点 `name` |
| 2 | JUDGE | 判断「知识点 X 的描述是 …」是否正确（错误项取他人描述） | 该点 `description` |
| 3 | MULTI | 4 组「知识点：描述」选出配对正确的两组（两对两错） | 两点的 `description` |
| 4 | SINGLE | 四个描述里哪个属于该知识点 | 该点 `description` |
| 5 | SINGLE | 该知识点属于哪个类别（兜底） | 该点 `category` |

前 4 类只依赖 `name` / `description`，因此在「类别全是概念」这类图谱上依然成立（第 5 类只作兜底）。
**关键性质：每道题的答案都由图谱事实唯一确定**，不会出现"造出来的题本身是错的"。LLM 生成题更自然但需人工审核，属后续工作（见第八节第 3 条）。

### 9.2 作答怎么造

- 每个学生分配一个能力值（强 / 中上 / 中 / 偏弱 / 弱），答对概率 = 能力值 − 难度修正 + 学习增益；
- 作答时间**回溯散布**在最近 N 天内（同一题多次作答逐次推进），用于展示遗忘曲线与时间衰减；
- 判分一律调用线上同一个 `grade()`，脚本末尾再做一次自洽性校验（把每条作答重新喂给 `grade()` 比对 `is_correct`），保证零口径偏差。

### 9.3 安全边界（只动自己造的数据）

| 数据 | 标记 | 重跑时的处理 |
|------|------|--------------|
| 演示题目 | `t_question.source = 'IMPORT'` | 仅删除本课程 + `source='IMPORT'` 的行 |
| 演示作答 | 依附于上述 IMPORT 题 | 只删除这些题产生的作答记录 |
| 演示学习标记 | `t_learning_record.source = 'SYSTEM'` | 只删除 `SYSTEM`，保留 `MANUAL` |
| 学生自评学习标记 | `t_learning_record.source = 'MANUAL'` | **跳过写入、绝不覆盖**（见下方说明） |
| 教师手工题 | `source = 'MANUAL'` | **永不触碰** |

**关于 MANUAL 学习标记（实测踩过的坑）**：`t_learning_record` 上有 `UNIQUE(user_id, course_id, kp_id)`，
若直接用 `upsert_learning_record` 回填，会把同一 (学生, 知识点) 上学生自己标记的记录**连 `source`
一起改成 `SYSTEM`**；下次重跑时的清理又会按 `source='SYSTEM'` 把它删掉 → 真实数据丢失。
因此 `seed_learning()` 会先取出该课程的 MANUAL 键集合，凡学生手动标记过的知识点一律跳过，
并在输出里打印跳过条数（如"跳过 6 条已有的 MANUAL 标记"）。

| 数据 | 是否入 git | 后果 |
|------|:---:|------|
| `backend/data/app.db`（课程 / 用户 / 密码哈希 / 文档记录 / 题目 / 学习记录 / 作答） | ✅ 入 | 每个人的**本地演示数据互相覆盖**：别人的课程会跑到你机器上（课程 63/64 即协作者 zane-a-wq 在提交 `269cd3d`（2026-09-13 22:29）带入的演示数据，其创建者 `demo_teacher(109)`/`demo_student(110)` 正是前端登录页硬编码的演示账号，密码 `demo123456`） |

   要么约定"图谱导出 JSON 随仓库走"（本脚本的 `--kp-json` 正是为此预留，
   导出/导入方式可复用 `backend/backup/neo4j_*.json` 的格式）；
3. 每次提交前用 `python seed_practice_data.py --course-id <你的演示课程> --dry-run` 自查，
   避免把临时数据带进仓库。

## 十、知识点题目覆盖率与 kp_id 完整性校验（P1）

### 10.1 为什么要做

`t_question.kp_id` 是**逻辑外键**（指向 Neo4j `KnowledgePoint`，不建物理外键），此前的写入路径
**完全不校验**：教师手输、从别的课程复制、图谱重建后旧 id 失效，都会写出「悬空知识点」的题目——
它们在「按知识点出题 / 推荐 → 练题」里**永远选不到**，且没有任何提示。

### 10.2 写入校验规则（`_check_kp_exists`）

| 情况 | 结果 |
|------|------|
| `kp_id` 为空 | 放行（题目允许不挂知识点） |
| 图谱可用，查无此点 | **4002**：`知识点不存在：course_id=.., kp_id=..（请从「关联知识点」下拉中选择本课程图谱中的知识点）` |
| 图谱不可用（连接异常等） | **放行**，并在响应里带 `kp_checked=False` —— 图库宕机不应阻塞教师建题 |

- 校验按**课程级**（`MATCH (n:KnowledgePoint {course_id})`，不带 `document_id`）：教师端的
  「关联知识点」下拉本就是聚合该课程全部文档的图谱节点，课程通用题尤其需要跨文档挂知识点。
- 生效范围：`create_question`（总是校验）与 `update_question`（**仅当本次显式传了 `kp_id`**——
  历史脏数据不应因"只改解析"而被拦住）。
- 顺带修复：**显式传 `kp_id=null` 现在能真正清空关联**。此前 `merged` 用 `is not None` 判断，
  把"清空"当成"未传"→ 前端点「清空知识点」静默失效（由 `test_question_coverage.py` 捕获）。

### 10.3 覆盖率报表

- 接口：`GET /api/v1/questions/coverage?course_id=&document_id=`（教师端，`require_teacher` + 课程归属校验）
- 口径：**只数启用中的题目**（停用的题出不出来，等同于没有题）；`document_id` 传入时统计
  「该文档题目 + 课程通用题」，知识点侧按该文档过滤。
- 返回字段：

| 字段 | 含义 |
|------|------|
| `total_kp` / `kp_with_question` / `kp_without_question` / `coverage_rate` | 知识点覆盖率 |
| `question_count` / `unlinked_question_count` | 启用中题目数 / 未挂知识点的题目数 |
| `dangling` / `dangling_count` | **悬空 kp_id**：题目引用的知识点已不在本课程图谱中 |
| `unmatched` | 无题知识点清单（含 `kp_id`/`name`/`category`/`document_id`） |
| `graph_available` | 图谱不可用时为 `false`，此时只返回题量统计（不整页报错） |

- 教师端入口：**题库 Tab → 第二层「知识点题目覆盖率」卡片**（KPI + 悬空知识点告警 +
  无题知识点标签，**点击标签直接打开新增题目表单并预填该知识点**，形成"补题"闭环）。

### 10.4 验证

- 服务层：`python test_question_coverage.py` → **通过 24/24**
  （真实 kp 通过 / 假 kp 4002 / 空 kp 放行 / 只改解析不拦 / 显式 null 清空 / 覆盖率与 DAO 统计一致 /
  停用后进入无题清单 / 悬空识别 / 文档级作用域 / 越权 4003 / 图库不可用降级 / 归零清理）
- 接口层（`fastapi.testclient` 联调）：无 token → 401（**证明 `/coverage` 未被 `/{question_id}` 吃掉**）、
  学生 token → 403、教师 → `code=0`（`total_kp=40, covered=40, rate=100%`）、
  不存在课程 → 2001、非整数 course_id → 4001、假 kp_id 建题 → 4002、
  原 `/questions/{id}` 与 `/questions/stats` 回归正常
- 回归：`python test_question_bank.py` → **通过 58/58**；前端 `npm run build` 通过

### 10.5 已知边界

1. **历史悬空数据不会被自动修复**：覆盖率报表只负责"指出来"，需要教师在题库里重挂知识点。
2. 覆盖率只反映"有没有题"，不反映题目质量（题干是否准确、难度是否合适）。
3. 图谱不可用时（`graph_available=false`）给不出"无题知识点 / 悬空"两项，属预期降级。

## 十一、题目推荐打分器（P2）

把"随机抽题"升级为"按学情选卷"：`app/services/question_recommender.py`（打分器）+
`PracticeService.recommend_questions`（防泄题投影 / 降级）+ `POST /api/v1/practice/recommend`。

### 11.1 八个信号（权重集中在模块常量，便于调参与实验）

| 信号 | 权重 | 含义 | 数据来源 |
|------|:---:|------|----------|
| ① 薄弱度 | 0.35 | 知识点掌握度越低越该练 | 轻量掌握度（练习表现 + 学生自评，读时计算） |
| ② 遗忘到期 | 0.20 | 距上次作答越久越该复习（7 天视为到期） | `t_answer_record.answered_at` |
| ③ 难度适配 | 0.15 | 目标难度 = 1 + 4·掌握度/100（最近发展区） | `t_question.difficulty` |
| ④ 新颖度 | 0.10 | 没做过 1.0 / 做过且错 0.5 / 做过且对 0.3 | `t_answer_record` |
| ⑤ 最近答错 | 0.10 | 最近一次答错的题优先 | `t_answer_record` |
| ⑥ 知识点重要性 | 0.10 | 图谱中度数越高的知识点越优先 | Neo4j 度数 `(n)--(m)` |
| ⑦ 题目区分度 | 乘性 ×0.7 | 全班正确率 <20% 或 >95%（≥3 次作答后）降权 | `question_answer_stats` |
| ⑧ 多样性配额 | — | 同知识点题数 ≤ ⌈N/3⌉、题型均衡、错题不刷屏 | 组卷阶段 |

轻量掌握度：`acc = Σ w_i·correct_i / Σ w_i`，`w_i = 0.5^(Δdays/14)`；与自评（MASTERED=1.0 /
LEARNING=0.5）按 0.5:0.5 融合；无练习数据时只用自评并在 `meta.mastery_available=false` 标注"证据不足"。

### 11.2 六种出题模式（分桶）

| mode | 说明 |
|------|------|
| `mixed`（默认） | 分层组卷：薄弱 40% / 复习 25% / 路径新知识 20% / 进阶 15%，桶内不足自动回填 |
| `weak` / `review` / `new` / `advanced` | 单桶模式；该桶无题时用其它桶回填并置 `meta.bucket_empty=true` |
| `random` | 随机基线（用于与现状对照、A/B 实验） |

### 11.3 接口与返回

`POST /api/v1/practice/recommend`（学生端，`get_current_user`）：

```json
{"course_id": 65, "document_id": 101, "kp_id": null, "q_type": null,
 "count": 10, "mode": "mixed", "seed": 42}
```

返回 `data.items[]`：**与该题一致的防泄题白名单字段**（`question_id/stem/options/...`，**无 answer/analysis**）
外加推荐附加信息：`reason`（推荐理由）、`bucket`/`bucket_label`（分桶）、`kp_name`、`mastery`、`attempts`、`score`。
`data.meta`：`buckets`（各桶实际数量，含 `filled`/`quota_relaxed`）、`kp_quota`、`candidates`、
`mastery_available`、`graph_available`、`next_kp_ids`、`weights`、`degraded`。
`seed` 用于复现同一批题（同 seed 结果一致，便于演示与 A/B）。

### 11.4 离线评估（`backend/eval_question_recommend.py`）

时间切分回测：每个学生的作答按时间排序后 **70% 训练 / 30% 测试**，只用训练集构造信号，
预测"未来答错的题"（最该练的题）。课程 65（5 名学生 / 120 题 / N=5，随机基线 30 次平均）：

| 策略 | HitRate@5 | Coverage@5 | NDCG@5 |
|------|:---:|:---:|:---:|
| 随机抽题（现状） | 0.095 | 0.387 | 0.1069 |
| 纯错题优先 | 0.011 | 0.200 | 0.0103 |
| **本打分器（mixed）** | **0.120** | **0.600** | **0.1555** |

结论：打分器在三个指标上均优于随机与"纯错题优先"（HitRate +26%、Coverage +55%、NDCG +45%）。
值得注意的是**"纯错题优先"反而最差**——因为学生未来出错的题多为"还没做过的新题"，
只重复错题无法覆盖；这正是多信号组卷的价值。

> ⚠ 数据说明：以上为**小规模合成数据**（作答由能力值模型生成），指标用于横向对比策略，不等于线上效果。
> 换成真实班级数据后应重跑该脚本。

### 11.5 已知边界

1. 权重是**经验值**（模块顶部常量），未做网格搜索调参；有真实数据后可用 `eval_question_recommend.py` 做权重消融实验。
2. 区分度信号依赖全班作答量（≥3 次才生效），冷启动阶段基本不参与。
3. 当前 demo 数据里"题型"与"难度"强相关（种子脚本按题型给难度），所以 `advanced` 桶更容易出现多选题；
   真实题库不受此影响。
4. 推荐只解决"选哪些题"，不解决"题目本身好不好"（题干质量、难度标注准确性）。

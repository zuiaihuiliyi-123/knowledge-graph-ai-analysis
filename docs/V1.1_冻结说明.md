# 知识抽取模块 V1.1 冻结说明

> 本文档定义知识抽取模块（`backend/app/services/knowledge_extractor.py` 及配套）的版本冻结纪律。
> 作用：明确「哪些能改、哪些不能改、什么条件下才能改」，避免评测阶段「追着数据调 Prompt」，破坏 Gold 测试集的独立性。

## 一、V1.1 定版（当前版本）

| 项 | 值 |
|----|----|
| 架构 | 单阶段 LLM（一次调用同时抽实体 + 关系） |
| Prompt | 决策树 + 负例约束（`EXTRACTION_PROMPT`，`prompt_version=v1.2`） |
| 分块 | `chunk_tokens=6000` |
| overlap | `overlap_tokens=400` |
| temperature | 开发 0.15 / 正式评测 0 |
| 关系类型 | PRECEDES / CONTAINS / RELATED_TO / APPLIES_TO |
| 校验 | 类型白名单、实体存在性、自环过滤、去重、confidence 阈值 |
| 证据 | evidence + confidence 入 Neo4j |
| 评测 | Gold 标注 → P/R/F1 → Relation Macro-F1 |

参数唯一事实来源：`backend/eval_config.py`（`make_config` / `save_config`），每次抽取实验自动落 `experiment_config.json`，保证「某结果由哪个 Prompt / 模型参数 / chunk 策略产生」可追溯。

## 二、不可修改区（正式 Gold 评测开始后冻结）

- Prompt version 与 Prompt 正文
- 实体 / 关系定义、关系决策树
- Entity normalization 规则
- `chunk max_tokens`、`overlap`、`temperature`、`max output tokens`、`confidence thresholds`
- 评测指标定义
- Gold 数据（**标注一旦开始，不再为迁就模型而修改**）

## 三、可调区（仅在有实验证据后进入下一版本）

- Prompt v1.2 及后续版本
- 新的负面示例、关系边界说明
- `_SYNONYM_MAP`
- threshold、overlap

每次调整必须产生明确的版本跃迁（如 v1.1 → v1.2）并附对应实验记录。

## 四、变更纪律

```
V1.1 冻结
    ↓
正式课程数据
    ↓
第一轮基线实验（temperature=0，不改任何代码）
    ↓
根据 Gold 数据发现问题（哪类关系最易错、PRECEDES 的 Precision、overlap 是否改善跨块召回）
    ↓
有证据才进入 V1.2（附实验记录与 experiment_config.json）
```

**禁止**：跑一次 → 感觉 XX 少了 → 改 Prompt → 再跑 → 感觉 YY 多了 → 再改。这会破坏测试集独立性，使评测失去意义。

## 五、口径（术语约定，全文固定）

- `confidence`（置信度）= 模型对当前抽取结果的**自评**，不代表真实准确率。
- `default_relation_confidence`（0.8）= 仅在模型未返回 confidence 时用于缺省值填充与工程数据完整性，**不参与** P/R/F1 准确率计算。
- 真实准确率仅由 Gold 标注 + `backend/eval_accuracy.py` 的 P/R/F1 计算得出。

相关：`docs/知识抽取准确率测试报告.md`（评测口径）、`backend/eval_overlap_ab.py`（overlap A/B）、`backend/eval_accuracy.py`（Gold P/R/F1）。

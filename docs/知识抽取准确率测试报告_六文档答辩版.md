# 知识抽取准确率测试报告（六文档答辩版）

> **Prompt 版本说明**：本报告使用 **v1.9.1**（在第 2 章之外新增化学第 1/4 章通用规则），D5/D6 因此属于开发集。**v1.8 原 Prompt 的无偏复测**见 [知识抽取准确率测试报告_六文档_v1.8.md](知识抽取准确率测试报告_六文档_v1.8.md)：整体关系 F1 均值 0.7168 / pooled 0.7635，D1–D4 达标、D5/D6 未达标（0.3625 / 0.3769）。两份报告并列阅读，不能只取其中一份。
>
> **结论先行**：本报告用项目真实的「文档解析 → 分块 → DeepSeek 抽取 → 合并去重」链路，对 **6 篇真实课程章节、3 门独立课程、169,438 字符、279 个金标准实体、293 条金标准关系**做了 **5 轮独立 API 抽取**。关系主指标（赛题申报口径）**六篇均值 F1 = 0.8263，六篇 pooled F1 = 0.8296**；实体 F1 均值 **0.8917**；人工分层抽样 **100 条关系 + 50 个实体全部判定正确**（Wilson 95% CI 下界分别为 **96.3% / 92.9%**）。另用一份**未参与提示词迭代的 PDF 文档**做格式与泛化验证：解析 17,380 字符，抽取 45 实体 / 36 关系，人工全量复核 **31/36 = 86.1%**（95% CI [71.3%, 93.9%]）。
>
> **赛题硬性指标全部超过要求**：6 篇计分文档（要求 ≥6）/ 3 门课程（≥2）/ 单章最少 38 个金标准知识点（≥20）/ 每篇 3–4 类关系（≥3）/ TXT + PDF 两种格式（≥2）/ 关系 F1 均值 0.8263 与人工准确率 100%（≥70%）。

## 1. 测试目的、范围与测试集

### 1.1 目的

量化系统「课程文档 → 分块 → LLM 抽取 → 实体/关系三元组」环节的抽取质量，并在**真实章节规模**下回答三个问题：

1. 抽取出的知识点与关系**对不对**（Precision / 人工抽样）；
2. 该抽的有没有**漏掉**（Recall / F1）；
3. 结论在什么口径下成立、在哪些条件下不成立（局限与披露）。

本报告**只测知识抽取**，不测 RAG 问答质量、学习路径推荐效果或前端交互。

## 2. 抽取链路、评测口径与冻结参数

### 2.1 真实抽取链路

本报告不使用 mock、不使用手写预测文件。每轮抽取都走项目生产代码：

```
TXT / PDF
  → DocumentParser（pdfplumber / 文本清洗）
  → chunk_text_for_llm（chunk=6000 tokens，overlap=400 tokens）
  → KnowledgeExtractor（DeepSeek deepseek-chat，并发 4）
  → _merge_results（按名去重、类型白名单、悬空端点过滤、置信度阈值）
  → 预测落盘 pred_*.json
  → eval_accuracy.py 离线评分
```

评测入口为 `backend/eval_accuracy.py --live`（全仓库唯一评分实现）。运行前设置 `EXTRACT_CACHE=0`，**确保每一轮都是真实 API 调用，不读旧缓存**。

### 2.2 匹配规则与主指标

- **实体匹配**：名称精确匹配；匹配前经冻结归一化（全角转半角、折叠空白、纯英文大写、冻结别名表，归一化版本 `n1`）。
- **关系匹配**：`(source, rel_type, target)` 三元组；关系类型仅限四类英文 Cypher 类型；方向必须一致。
- **主指标 `relation_primary`（赛题申报口径）**：
  - Precision = |Pred ∩ Full| / |Pred|（Full = 金标准全部关系）
  - Recall = |Pred ∩ Core| / |Core|（Core = 文本明确、无争议关系）
  - F1 = 2PR / (P+R)
- **同时披露**：
  - `F1_core`：P/R 都只算 Core，保守下界；
  - `F1_full`：P/R 都只算 Full，严格口径；
  - 按关系类型 P/R/F1、Macro-F1、方向错误率、错误五分类、对账等式；
  - 人工抽样准确率（Precision）与 Wilson 95% 置信区间。
- `confidence` 是模型自评，**不参与任何 P/R/F1 计算**；它只用于工程侧的阈值过滤与诊断。

## 4. 误差分析：为什么自动 F1 低于人工准确率

### 4.1 先给结论

自动评测的 F1（0.8263）与人工抽样的 Precision（100%）**不是矛盾**：

- 人工抽样只回答“系统输出的这条关系本身对不对”，**不惩罚漏抽**；
- 自动 F1 同时惩罚漏抽（Recall）和“金标准未收录但语义合理”的输出（Precision）；
- 本项目的金标准是**选择性标注**（每章 33–74 条关系），而模型输出是**尽量完整**的（每章 39–82 条），差额中相当一部分是“合理但 Gold 未标”的关系。

### 4.2 错误五分类（5 轮合计）

| 类别 | 5 轮合计 | 单轮均值 | 说明 |
|---|---:|---:|---|
| ① 臆造（节点对不在 Full） | 54 | 10.8 | 其中相当一部分是“Gold 未收录但人工复核成立”的关系 |
| ② 方向颠倒 | 9 | 1.8 | 真实缺陷，主要出现在 D1/D3/D5 |
| ③ 类型混淆 | 0 | 0 | v1.9.1 修正“量纲分析”口径后降为 0 |
| ④ 同义拆分 | 0 | 0 | 归一化与去重生效 |
| ⑤ 完全漏抽（Core） | 36 | 7.2 | 真实缺陷，D3 的 APPLIES_TO 漏抽最多 |
| 评分前丢弃：重复三元组 | 202 | 40.4 | 主要来自跨 chunk overlap，工程去重，不计入准确率 |
| 评分前丢弃：低置信度 | 0 | 0 | 本阈值下未触发 |

**对账**：5 轮原始输出合计 517 条 = 计分 312 条 + 评分前丢弃 205 条；每篇每轮的 `原始 = 计分 + 丢弃` 均成立（见各篇 `eval_report` 的 `accounting` 字段）。

### 4.3 D6 的典型案例（最低分章，0.7525）

D6 的 FP 中有大量“金标准未收录但语义成立”的关系，例如：

- `SI基本单位 CONTAINS 长度/时间/温度`：原文表 1.2 把长度、质量、时间、温度列为基础量；
- `元素 CONTAINS 金属/非金属/类金属`：原文明确把元素分为这三类；
- `道尔顿原子理论 RELATED_TO 原子/化合物/物质守恒定律`：原文明确给出道尔顿理论的微观解释；
- `科学方法 CONTAINS 科学定律`：原文把定律、假说、理论都列为科学方法的环节。

这些关系在**人工抽样中全部判定正确**，但因为 D6 的 Gold 只收了其中一部分，自动 Precision 被拉低。反过来，D6 的真实缺陷是：

- `平均原子质量 PRECEDES 原子质量`（方向/类型不当，应为 RELATED_TO 或反向）；
- 少量方向颠倒（1 条）与完全漏抽（7 条 Core，如 `测量 RELATED_TO 不确定度`、`物质守恒定律 APPLIES_TO 化学变化`）。

### 4.4 D5 的典型案例（0.7641，最低轮 0.6967）

- **类型/方向**：模型把“定量分析 → 滴定分析/重量分析”的方向写反过一次，把“分子方程式 → 完全离子方程式 → 净离子方程式”的先后关系写成 RELATED_TO；v1.9.1 加入 PRECEDES 规则后已显著改善。
- **重复**：D5 单轮原始关系 62–81 条，去重后 39–48 条，去重率高是因为跨 chunk 的同一三元组重复输出；这是工程侧 merge 的正常现象，不影响最终计分。
- **采样波动**：第 4 轮 0.6967，低于 0.70 约 0.0033；5 轮均值 0.7641，说明单轮抖动不应被当作能力下降。

### 4.5 D1/D3 的采样波动

D1 的 5 轮标准差 ±0.0271、D3 ±0.0326；D1 第 4 轮 0.8767、第 1 轮 0.8056，同一 Prompt、同一模型、同一温度下相差 0.07。这说明**单轮结果不足以代表系统能力**，也是本报告坚持 5 轮均值 + 逐轮披露的原因。该现象与项目已知的“temperature=0 仍有波动”一致，属于外部 LLM 服务的采样不确定性，不是代码改动。

## 5. 人工抽样验证（赛题“人工抽样验证”口径）

### 5.1 抽样设计

- 母本：6 篇最终预测的**第 1 轮**输出，去重后关系池 **312 条**、实体池 **332 个**。
- 分层抽样：关系按类型分层（CONTAINS / RELATED_TO / APPLIES_TO / PRECEDES），每类保底，剩余按池子比例分配；实体按类别（概念 / 定理 / 公式 / 方法）分层。
- 样本量：**关系 100 条 + 实体 50 个**。
- 随机种子：`20261114`；同一批预测 + 同一种子可抽出完全相同的样本。
- 判定依据：**只看原文与系统输出，不打开 Gold**；判定表与原文上下文由 `scripts/sample_for_manual_check.py` 自动生成。
- 判定规则（与 `docs/人工抽样验证方案.md` 一致）：
  - 关系：正确 / 错误-臆造 / 错误-方向反 / 错误-类型错 / 错误-端点不成立；
  - 实体：正确 / 错误-臆造 / 错误-粒度不当 / 错误-类别错；
  - 不确定项留空，不计入分母，但单独披露（本次无留空）。

> **判定独立性说明**：判定以原文为准。对 4 条语义边界条目（如 `SI基本单位 CONTAINS 质量`、`斜率 RELATED_TO 位置-时间图`）在**判定完成后**对照了 Gold 的 `core` 标记，用于确认项目既有口径；未据 Gold 改动任何判定结论，相关备注已写入判定表。

| RELATED_TO | 40 | 40 | 40 | 1.0000 | [0.9124, 1.0000] |

- PRECEDES 只有 8 条，区间较宽（下界 0.6756），这是小样本的正常现象；主结论以合计 100 条的区间为准。

## 7. 合规性、局限与风险披露

### 7.1 合规性

1. **真实调用**：6 篇 × 5 轮 = 30 次独立抽取，全部通过 `KnowledgeExtractor` 调用 DeepSeek；`EXTRACT_CACHE=0`，未使用旧缓存。
2. **先落盘再评分**：每轮预测写入 `pred_*.json`，评分阶段只读该文件，不再调用 LLM；评分可反复复算。
3. **Gold 冻结**：评分前 Gold 已冻结并记录 SHA256；未在预测后修改任何实体、关系、方向或 `core`。
4. **不挑选轮次**：5 轮全部报告，最低轮（D5 0.6967）如实披露，不剔除、不重跑选优。
5. **口径可复核**：评测器、别名表、归一化版本、Prompt 版本、参数快照、预测文件、日志全部留档。
6. **许可**：OpenStax 教材为 CC BY 4.0；《Hello 算法》为 CC BY-NC-SA 4.0；仅用于教学评测与竞赛材料，报告中标明来源。

### 7.2 局限（评委最可能追问的四点）

1. **本体约束不是零样本泛化**：v1.9.1 的 Prompt 注入了学科本体规则。这是知识图谱构建的标准做法，但高分部分来自领域先验，不能直接等同于“面对完全陌生学科、无任何本体提示”的能力。PDF 独立文档（86.1%）是对这一局限的部分缓解，但不是完整答案。
2. **Gold 的选择性标注**：自动 F1 的 Precision 受 Gold 覆盖度影响；人工抽样 100% 说明模型输出的事实性很好，但不能反推“自动 F1 应该等于 1”。两者必须并列阅读。
3. **采样波动**：同一配置下 D1 的 5 轮从 0.8056 到 0.8767，D5 从 0.6967 到 0.8000。5 轮均值降低了点估计的不确定性，但没有消除。生产环境建议保留多轮投票或人工审核入口。
4. **测试集规模**：6 篇 / 293 条关系是“真实章节规模”的评测，不是大规模 benchmark；结论应限定在“本报告测试集 + 本配置”内。

### 7.3 temperature=0 对照（诚实披露）

为回应“0.3 是否有意挑选有利温度”的质疑，本报告另做了 temperature=0 的 3 轮对照：

| 文档 | temp=0.3（5 轮） | temp=0（3 轮对照） | 说明 |
|---|---:|---:|---|
| D1 | 0.8318 | 0.8141 | 基本一致 |
| D2 | 0.8829 | 0.8895 | 基本一致 |
| D3 | 0.8305 | 0.8109 | 基本一致 |
| D4 | 0.8962 | 0.8961 | 基本一致 |
| D5 | 0.7641 | **0.6765** | 该章对采样敏感，temp=0 反而低于 0.70 |
| D6 | 0.7525 | 0.7797 | 基本一致 |

**结论**：主协议 0.3 的 5 轮均值全部 ≥ 0.70；temp=0 对照中 D5 低于 0.70，说明“单一温度、单一轮次”都不足以支撑结论。本报告选择 0.3 + 5 轮，是在**赛前冻结的协议**下执行的，不是事后挑温度；同时如实披露 D5 的温度敏感性。

## 9. 评委可能提问与回答（答辩预设）

### Q1：你说的“准确率”到底是 Precision、Recall 还是 F1？

**答**：三个都报，且分开报。赛题原文写的是“知识抽取的准确率（人工抽样验证）”，按赛题口径它就是 **Precision（正确条数 / 判定条数）**，我们的人工抽样结果是 100/100，95% CI [96.3%, 100%]。但只看 Precision 会掩盖漏抽，所以我们同时报了自动评测的 **P / R / F1**：关系主指标 F1 均值 0.8263，pooled 0.8296，P 0.7981，R 0.8636。两个口径都 ≥70%。

### Q2：金标准是谁标的？会不会“自己标自己”？

**答**：Gold 由人工按统一决策树标注，每条关系带原文逐字 evidence；`scripts/validate_gold.py` 程序校验 evidence 逐字存在、端点合法、无自环、类型合法、`core` 为布尔。评分前 Gold 冻结并记录 SHA256；预测先落盘，评分只读落盘文件。D5/D6 只做了形式修复（缺 confidence、2 条 evidence 含省略号），修复记录逐条可查，**没有改任何实体、关系、方向或 core**。

### Q3：为什么只有 6 篇？为什么不是 20 篇？

**答**：赛题要求“至少 6 篇/至少 2 门课/单章 ≥20 知识点/≥3 类关系/≥2 种格式”，我们做到 6 篇计分 + 1 篇 PDF、3 门课、单章最少 38 个 Gold 知识点、每篇 3–4 类、TXT+PDF。继续加文档的边际收益低、标注成本高；6 篇已经覆盖 169,438 字符、293 条关系，是“真实章节规模”而不是玩具规模。

### Q4：为什么 D5 有一轮只有 0.6967，低于 70%？

**答**：这是单轮采样波动，不是剔除后的结果。D5 五轮是 0.7974 / 0.8000 / 0.7990 / 0.6967 / 0.7273，均值 0.7641，标准差 0.0488；30 轮里 29 轮 ≥0.70。我们坚持报告全部轮次，不挑最好一轮。D5 的主要误差是 PRECEDES/APPLIES_TO 的类型口径与跨 chunk 重复，已在 v1.9.1 中修正类型规则；剩余波动来自外部 LLM 采样。

### Q5：为什么自动 F1 只有 0.82，人工抽样却是 100%？是不是人工抽样放水？

**答**：不是。两个口径测的不是同一件事：人工抽样只判断“系统输出的这条关系本身对不对”，**不惩罚漏抽**；自动 F1 同时惩罚漏抽和“Gold 未收录但语义合理”的输出。D6 的 FP 里大量是 `SI基本单位 CONTAINS 长度/时间/温度`、`元素 CONTAINS 金属/非金属/类金属` 这类原文明确支持、但 Gold 没收的关系；人工复核判正确，自动评测仍算 FP。我们把这个差额原样披露，而不是只报大的那个数。

### Q6：本体约束（ontology-guided）算不算“泄题”或过拟合？

**答**：本体是领域知识的组织结构（“化学键包含共价键/离子键”“复杂度分析包含时间/空间复杂度”），不是答案；模型仍要从原文分块中真实抽取，Gold 没有被修改，模型也输出 Gold 之外的关系。我们明确披露这是本体约束抽取，不把它包装成零样本泛化。为了检验泛化，我们加了一份**未参与提示词迭代**的 PDF 文档（Python 面向对象），人工复核 31/36 = 86.1%，CI 下界 71.3%，说明规则不是只对调过的章节有效。

### Q7：为什么用 DeepSeek？换模型会不会更好？

**答**：DeepSeek 在中文教材抽取上成本/质量平衡好，且项目已有稳定 API 接入。评测器与 Prompt 是模型无关的，换模型只需改 `LLM_MODEL` 并重跑同一套 gold；本报告的意义是给出**可复现的测量方法**，不是宣称某个模型绝对最优。

### Q8：5 轮是不是在“刷分”？为什么不是 1 轮？

**答**：单轮波动很大：D1 五轮从 0.8056 到 0.8767，D5 从 0.6967 到 0.8000。如果只跑 1 轮，报哪个数都有挑选嫌疑。5 轮均值 + 标准差 + 逐轮值，是更诚实的做法；而且我们把最低轮也报出来了。代价是 API 调用量增加，但换来的是可辩护的结论。

### Q9：换一篇新文档，现场能跑吗？没有 Gold 怎么算准确率？

**答**：能。上传 PDF/TXT/DOCX/MD → `DocumentParser` 解析 → `KnowledgeExtractor` 抽取 → 入 Neo4j/SQLite。没有 Gold 时，用 `sample_for_manual_check.py` 对输出分层抽样，人工按原文逐条判定，`calc_manual_accuracy.py` 给出 Wilson 区间；这就是赛题“人工抽样验证”的口径。PDF 文档已经完整跑通过一次。

### Q10：结果可复现吗？

**答**：可复现。`prepare_report6.py` 固定文本与 Gold 并输出 SHA256；`run_report6.py` 固定模型、temperature、chunk/overlap、5 轮、关闭缓存；预测文件先落盘；人工抽样固定种子 20261114；所有报告数字由 `eval_accuracy.py` / `calc_manual_accuracy.py` 自动生成，不手抄。唯一不可完全复现的是 LLM 自身采样波动，所以我们报 5 轮均值 ± 标准差，而不是一个“精确到小数点后四位”的单轮数字。

### Q11：抽取错了怎么办？教师能改吗？

**答**：可以。教师端已支持图谱节点/关系的手动增删改；抽取结果带 confidence 与 evidence，低置信度可人工复核。工程侧还有类型白名单、悬空端点过滤、跨 chunk 去重、置信度阈值等兜底。本报告测的是“自动抽取的质量”，不是“自动抽取不可修正”。

### Q12：为什么关系只有 4 类？够吗？

**答**：赛题要求 ≥3 类。4 类覆盖了课程知识图谱最核心的语义：上下位/组成（CONTAINS）、学习前置（PRECEDES）、方法应用（APPLIES_TO）、一般关联（RELATED_TO）。类型过多会带来标注一致性和模型判别难度；当前 4 类已经能支撑学习路径 BFS（PRECEDES）与 RAG 子图检索。后续可按学科扩展，但需要重新做标注一致性验证。

### Q13：你们的测试集是不是“开发集”，分数会偏高？

**答**：D1–D4 是项目既有开发集，D5/D6 是新增扩展集；v1.9 的化学规则确实参考了第 1/4 章的错误模式，所以 D5/D6 的最终分数应理解为**开发集分数**，不是无偏泛化。为了部分弥补，我们加入了未参与迭代的 PDF 文档（86.1%）作为独立检查。报告里明确写了这一点，不把开发集分数说成泛化能力。

### Q14：为什么 D5 在 temperature=0 反而低于 70%？

**答**：说明该章对采样路径敏感，单温度/单轮次都不足以支撑结论。我们的主协议是赛前冻结的 0.3 + 5 轮，D5 均值 0.7641；temp=0 的 3 轮对照是 0.6765。我们把这个对照原样放在 §7.3，而不是删掉。工程上的应对是多轮投票、提高轮次、或对 D5 这类高方差章节加人工复核。

### Q15：这份报告和之前的《知识抽取准确率测试报告》是什么关系？

**答**：之前的报告覆盖 4 章、3 轮、v1.8，四章均值 0.8920；本报告覆盖 6 章、5 轮、v1.9.1，六章均值 0.8263。新增的 D5/D6 是更难的化学章节，把整体均值拉低是正常的；D1–D4 仍全部 ≥0.83。本报告不替换旧报告，而是作为**答辩版扩展报告**：文档更多、轮次更多、含人工抽样与 PDF 独立验证、含逐条局限披露。

## 10. 结论

1. **在 6 篇真实章节、3 门课程、169,438 字符、279 实体 / 293 关系的规模下，知识抽取关系主指标 F1 六篇均值 0.8263、pooled 0.8296，全部超过赛题 70% 线；人工抽样 100 条关系 / 50 个实体准确率 100%，Wilson 95% CI 下界 96.3% / 92.9%。**
2. **赛题的文档数、课程数、单章知识点数、关系类型数、文档格式数五项硬性指标全部超过要求。**
3. **方法迭代有效**：v1.8 → v1.9.1 使化学第 4 章 0.2947 → 0.7641、第 1 章 0.3441 → 0.7525，且未修改任何 Gold。
4. **误差主要不是“胡编”**：人工抽样未发现事实错误；自动 Precision 的损失主要来自 Gold 的选择性标注、类型/方向口径差异与跨 chunk 重复，报告已逐类披露。
5. **局限已披露**：本体约束、开发集偏差、单轮波动、测试规模；PDF 独立文档 86.1% 是对泛化局限的部分缓解，不构成完整证明。

# 一键启动说明

仓库提供跨平台启动脚本，把「检查环境 → 安装依赖 → 启动 Neo4j（可选）→ 启动后端 → 启动前端」串成一条命令。

主脚本位于 `scripts/start.py`；仓库根目录的 `start.py` / `start.bat` / `start.sh` 是兼容入口，因此下面两种写法等价：

```bash
python start.py
python scripts/start.py
```

## 1. 使用方式

| 系统 | 操作 |
|---|---|
| Windows | 双击 `start.bat`，或在仓库根目录执行 `python start.py` |
| macOS / Linux | 在仓库根目录执行 `./start.sh`，或 `python3 start.py` |

启动成功后：

- 前端：<http://127.0.0.1:5173>
- 后端健康检查：<http://127.0.0.1:8000/health>
- 接口文档：<http://127.0.0.1:8000/docs>

按 `Ctrl+C` 会停止**由本脚本启动**的进程。如果前后端原本就已在运行，脚本会识别并复用，不会重复启动，也不会杀掉已有进程；只有端口被**其他程序**占用时才会报错。

## 2. 环境要求

| 组件 | 要求 | 说明 |
|---|---|---|
| Python | 3.12 推荐；3.13 可用 | `backend/requirements.txt` 已按 Python 版本区分 numpy（3.13+ 用 2.5.3） |
| Node.js | 20.19+ 或 22.12+ | Vite 7 的要求；`npm` 随 Node 安装 |
| Neo4j | 可选 | 本地或远程均可；没有 Neo4j 时前后端仍能启动，但图谱/路径/问答功能降级 |
| 数据库文件 | 不需要准备 | SQLite 在后端首次启动时自动建库建表 |

首次运行时脚本会自动：

1. 查找可用的 Python 解释器；找不到完整依赖时自动在项目根目录创建 `.venv` 并执行 `pip install -r backend/requirements.txt`；
2. 在 `frontend-vue/node_modules` 缺失时执行 `npm install`；
3. 缺少 `backend/.env` 时从 `.env.example` 复制一份并提示填写密钥。

> 自动安装依赖需要联网。若机器不能联网，请先按 `backend/requirements.txt` 与 `frontend-vue/package.json` 准备依赖，再用 `--no-install` 启动。

## 3. 数据库说明（重要）

项目有**两套存储**，一键启动对它们的处理不同：

| 存储 | 内容 | 一键启动行为 |
|---|---|---|
| SQLite | 用户、课程、文档、题库、作答、向量等 | 嵌入式文件库，**无需单独启动**；后端首次启动自动创建 |
| Neo4j | 知识点节点与关系 | 外部服务。脚本优先连接 `backend/.env` 的 `NEO4J_URI` |

Neo4j 的处理顺序：

1. `NEO4J_URI` 指向非本机（如 Neo4j Aura / 远程服务器）：只做连通性检查，不在本机启动；
2. `NEO4J_URI` 指向 localhost 且 7687 已监听：直接复用，并用 `.env` 凭据做一次连接校验；
3. 本地端口未监听：依次查找
   - 环境变量 `NEO4J_HOME`
   - `--neo4j-home` 参数
   - PATH 里的 `neo4j` / `neo4j.bat`
   - `~/Downloads/neo4j-community-*`、`~/neo4j-*`、`/opt/neo4j*`、`/usr/local/neo4j*`、`C:\Program Files\Neo4j*` 等常见解压目录
4. 找到则启动 `neo4j console` 并等待 7687 就绪；找不到/启动失败/认证失败时**只告警**，继续启动前后端。

因此：

- **数据库可用**时，一键启动包含图数据库；
- **数据库不可用**时，脚本仍会把前后端拉起来，这正是「数据库不行，前后端同时一键启动」的兜底路径；
- 真正“复制到任何电脑都能连数据库”不能只靠本脚本：Neo4j 本身需要安装/远程实例，或改用 Docker/云端 Neo4j。需要完全零安装时，建议后续提供 `docker compose` 或把前端构建产物交给后端托管。

## 4. 常用参数

```bash
python start.py --check          # 只检查环境/端口/数据库，不启动、不安装
python start.py --backend-only   # 只启动后端
python start.py --frontend-only  # 只启动前端
python start.py --no-db          # 跳过 Neo4j 检查与启动
python start.py --no-install     # 缺少依赖时直接报错，不自动安装
python start.py --no-browser     # 启动后不自动打开浏览器
python start.py --reload         # 后端启用 uvicorn --reload
python start.py --neo4j-home "D:/neo4j/neo4j-community-2026.07.1"
python start.py --python "C:/Python312/python.exe"
```

`--check` 返回码：`0` 表示未发现阻塞项；`1` 表示端口冲突或依赖/环境有问题。

## 5. 常见问题

### 端口被占用

脚本启动前会检查 8000（后端）与 5173（前端）：

- 如果占用者就是本项目的服务（会校验 `/health` 与页面标题），直接复用，只启动缺失的一端；
- 如果是其他程序占用，才会报错并提示先关闭，避免出现“新进程起不来、旧进程还在跑”的假启动。

### Neo4j 报认证失败

`.env` 里的 `NEO4J_PASSWORD` 必须与 Neo4j 实例一致。脚本只会提示，不会修改 Neo4j 口令。新建的 Neo4j 实例默认口令通常需要先在 Neo4j 端完成初始化。

### 前端能打开但登录/图谱报错

先看一键启动终端里的 `[后端]` 日志：

- 没有 `LLM_API_KEY`：知识抽取/问答生成不可用；
- 没有 `EMBEDDING_API_KEY`：RAG 静默退回关键词检索；
- 没有 Neo4j：图谱相关接口降级；
- 首次启动的引导账号口令只在后端日志中打印一次，请从 `[后端]` 输出里抄取。

### 依赖安装失败

优先使用 Python 3.12；Python 3.13 已通过 requirements 的版本标记支持。若使用代理/镜像，请先配置好 `pip` 与 `npm`。

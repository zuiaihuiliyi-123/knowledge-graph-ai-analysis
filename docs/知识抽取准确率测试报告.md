# 知识抽取准确率测试报告

> 交付物对应赛题「知识抽取测试报告」。本报告在**真实章节规模**（15330 字符 / 49 实体 / 33 关系）下记录知识抽取的完整 **基线测量 → 错误归因 → Prompt 迭代 → 复测验证** 闭环，最终关系主指标 F1 达到 0.8312，超过赛题 70% 准确率要求。
>
> 本报告所有数字由 `backend/eval_accuracy.py`（全仓库唯一评测实现）自动计算，原始结果见 `backend/eval_data/eval_report_第7章_树_v15.json`，渲染版见 `backend/eval_data/评测报告_第7章_树_v15.md`。提示词迭代过程见《提示词工程完整记录》§2.3~2.4。

---

## 一、测试目的

量化系统「课程文档 → 分块 → LLM 抽取 → 三元组」环节的抽取质量，在真实章节规模下定位系统性错误、迭代提示词并验证修复效果，使「知识抽取准确率 ≥70%」这一赛题指标站得住。

## 二、测试对象与方法

### 2.1 测试源文本

- **文本**：《Hello 算法》第 7 章「树」（CC BY-NC-SA 4.0），清洗后 **15330 字符**，按项目分块器（chunk 6000 tokens / overlap 400 tokens）切分后并发 4 路调用。
- **规模意义**：此前报告的 0.93 出自 708 字节 / 11 行的玩具文本（5 实体 / 4 关系），与真实章节规模不可比（见 §七 规模对比）。

### 2.2 金标准（人工标注，预测前冻结）

- 文本：`backend/eval_data/第7章_树.txt`；金标准：`backend/eval_data/gold_第7章_树.json`
- 规模：**49 实体 / 33 关系**（CONTAINS 25 / RELATED_TO 5 / APPLIES_TO 3 / PRECEDES 0），每条关系携带原文 evidence、confidence 与 core 标记
- 冻结：Gold SHA256 `50f316ce7bea6690…`；标注口径见 `backend/eval_data/第7章_树_标注说明.md`（含决策树执行记录与边界判定）

### 2.3 评测口径（`backend/eval_accuracy.py`，全仓库唯一实现）

- **实体**：名称精确匹配，经冻结归一化（全角转半角 + 折叠空白 + 纯英文大写 + 20 条冻结别名表，版本 `n1`，别名表 SHA256 随报告输出）
- **关系主指标 `relation_primary`（赛题申报口径）**：
  - Precision = |Pred ∩ Full| / |Pred|（Full 集 = 金标准全部关系）
  - Recall = |Pred ∩ Core| / |Core|（Core 集 = 文本明确、无争议的关系）
  - 模型输出仍须落在 Full 集内才算对；方向错误、类型错误、臆造全额扣分
- **辅助指标**：`relation_core`（保守下界）、`relation_full`（严格匹配）、实体类别准确率、按关系类型 P/R/F1、方向错误率、错误归因五分类（臆造 / 方向颠倒 / 类型混淆 / 同义拆分 / 漏抽）、对账等式（模型原始输出 = 进入评分 + 评分前丢弃）
- `confidence` 是模型自评置信度，**不参与任何 P/R/F1 计算**

### 2.4 实验参数（冻结快照 `experiment_config_*.json`）

| 参数 | 值 |
|------|-----|
| Prompt 版本 | v1.2（基线）/ v1.5（定稿） |
| 模型 | deepseek-chat |
| temperature | 0（正式评测） |
| chunk / overlap | 6000 / 400 tokens |
| 并发 / 轮次 | 4 / 3 轮独立运行 |

## 三、基线结果（Prompt v1.2）

第 7 章·树在 v1.2 下的 3 轮均值：

| 指标 | 值 |
|------|-----|
| 实体 F1 | 0.6247 ± 0.0552 |
| 关系主指标 Precision | 0.1348 |
| 关系主指标 Recall | 0.2020 |
| **关系主指标 F1** | **0.1614** ± 0.0121 |
| 方向错误率 | 0.1346 |
| 逐轮 F1 | 0.1519 / 0.1750 / 0.1573 |

**同一套抽取链路，规模从 708 字节放大到 15330 字符，关系 F1 从 0.93 掉到 0.16**——玩具规模的 0.93 不能支撑赛题申报，必须按真实规模修复。

## 四、问题定位（v1.2 错误归因，每轮均值）

| 错误类别 | 数量 | 根因 |
|----------|:----:|------|
| ① 臆造 | 31 | 决策树"整体-部分"分支使模型把组成/属性关系全判 CONTAINS（二叉树 CONTAINS 叶节点/高度…）；代码符号误抽（==、BUILD_TREE()）；「平衡因子 PRECEDES 旋转」类硬造前置 |
| ② 方向颠倒 | 5~16 | **CONTAINS 方向系统性颠倒**：「X 是 Y 的一种」输出成 X CONTAINS Y（如 AVL 树 CONTAINS 二叉搜索树） |
| ③ 类型混淆 | 4 | 遍历子类关系误判 APPLIES_TO（深度优先遍历 APPLIES_TO 中序遍历） |
| ④ 同义拆分 | 0 | — |
| ⑤ 漏抽（Core） | 27 | 未抽「遍历」「旋转」等类别性总称（连带漏 8 条）；APPLIES_TO 与 gold 决策树冲突（Prompt 禁止「基于…实现」映射，但 gold 标注「递归 APPLIES_TO 深度优先遍历」） |

按关系类型：CONTAINS F1=0.235，RELATED_TO 与 APPLIES_TO **均为 0**（方向随机 + 类型泛化）。

## 五、修复措施（v1.3 → v1.5，详见《提示词工程完整记录》§2.3）

**v1.3**（对齐 gold 决策树）：CONTAINS 收紧为「类型包含 + 操作包含」两类并新增方向自检与反例集；APPLIES_TO 重写为「实现机制的正确映射」（方法→问题，数据结构降级 RELATED_TO）；RELATED_TO 增加方向约定（工具/支撑方为 source）；PRECEDES 增加「X 是理解 Y 的关键」反例；要求「类别性总称必抽」。

**v1.4**（定向修复）：实体 category 判定细则（遍历类→方法）；定义句上位词抽取；「历史上反复出错的输出」禁止清单（点名 3 条 CONTAINS 方向错误）；组成/属性关系点名禁止；**代码层兜底过滤**（`_is_code_symbol` 过滤函数调用、运算符、关键字，不依赖 LLM）。

**v1.5**（只加反例的收敛微调）：代码注释操作描述不抽；操作关系主体必须明确；「表示法不是 APPLIES_TO」反例；RELATED_TO 增补正反例（思想来源 / 维护机制禁止 / 共享词根禁止）。

## 七、残余误差分析（v1.5）

剩余 10 条误差（5 臆造 + 5 漏抽）性质如下：

- **臆造 5 条**：「二叉树 CONTAINS 节点」（组成关系反例已入 Prompt，模型偶发再犯）、「完美二叉树 RELATED_TO 高度」等属性关联——均属 Prompt 已覆盖但 LLM 偶发越界，非系统性缺陷。
- **漏抽 5 条**：「链表」「非线性数据结构」「平衡二叉搜索树」3 个实体在文本中出现频次极低（各 1~2 次），跨 3 轮均未召回，属小频次实体边界；「AVL 树 RELATED_TO 红黑树」「二叉搜索树 APPLIES_TO 多级索引」在 v1.3/v1.4 轮次中曾正确命中，属轮次波动。
- **对账**：3 轮均满足「模型原始输出 = 进入评分 + 评分前丢弃」，无未记账的丢弃路径。

## 八、结论

1. **真实章节规模下关系主指标 F1 = 0.8312（P=0.7841，R=0.8889），超过赛题 70% 准确率要求，且 3 轮全部超线（最低 0.8000）、逐轮稳定（std=0.027）。**
2. 提升来自四次定向修复：v1.3 对齐 gold 决策树（F1 0.16→0.56）→ v1.4 方向自检与代码兜底（→0.77）→ v1.5 反例收敛（→0.83）。方向错误率从 13.5% 清零，CONTAINS F1 达 0.939。
3. 修复成本全部在提示词与数据完整性兜底层，未改动评测口径与金标准——证明「错误归因驱动的 Prompt 迭代」是提升抽取质量的第一杠杆。
4. **后续验证计划**：开发集（本报告）达标后，封存集（物理·第 2 章 运动学 / 数据结构·第 2 章 复杂度分析）gold 标注完成后只跑一次，作为最终验证进入交付材料。

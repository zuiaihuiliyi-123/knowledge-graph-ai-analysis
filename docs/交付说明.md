# 项目交付说明（Phase 10 收尾版）

> 基于 AIGC 的课程知识图谱智能构建与学习导航系统（A10 服务外包大赛）
> 数据模型：`Course → Document[] → KnowledgeGraph[] → KnowledgePoint[] → Relation[]`

---

## 1. 项目运行说明

- **后端**：FastAPI（`backend/`），统一响应 `{code, message, data, timestamp}`，JWT 鉴权。
- **前端**：Vue 3 + Vite 7 + Element Plus + AntV G6 + Pinia（`frontend-vue/`）。
- **图数据库**：Neo4j（本地实例，`KnowledgePoint` 节点 + 中英文关系类型 `PRECEDES/CONTAINS/RELATED_TO/APPLIES_TO`）。
- **关系库**：SQLite（`backend/data/app.db`，`t_` 前缀表；学习记录/收藏/向量三类文档级业务数据 + 课程/文档/用户元数据）。
- **RAG**：Embedding 走 SiliconFlow `BAAI/bge-m3`（OpenAI 兼容），LLM 走 DeepSeek `deepseek-chat`。

## 3. Neo4j 启动说明

- 本地 Neo4j（版本 2026.07.1，测试通过；**无 APOC 插件**）。
- 连接串：`bolt://localhost:7687`，用户 `neo4j`，密码见 `backend/.env` 的 `NEO4J_PASSWORD`。
- 首次启动后无需手工建约束；后端 `db.init_schema()` 幂等初始化。

## 6. 数据库说明

- **SQLite**（`data/app.db`）：`t_user` / `t_course` / `t_document` / `t_kp_embedding` / `t_learning_record` / `t_student_favorite` / `t_question` / `t_answer_record` / `t_question_favorite`。
  - 文档级业务表（embedding/learning/favorite）均含 `document_id`，UNIQUE 保持 `(user_id, course_id, kp_id)`（kp_id 全局唯一）。
  - 题库三表：题目（`options`/`answer` 存 JSON 文本）、答题记录（追加式，不建 UNIQUE）、题目收藏（`UNIQUE(user_id, question_id)`）；删除题目/文档/课程时按「子表 → 主表」显式清理，避免孤儿数据。
  - `PRAGMA foreign_keys=ON`。
  - **`app.db` 不入版本库**（见根目录 `.gitignore`）：**克隆后无需准备任何 db 文件**，后端首次启动时 `sql_db.init_tables()` 会自动建库、建表并跑幂等迁移。历史上它曾被提交，导致换机器后「文档记录说已抽取完成、Neo4j 里却没有节点」→ RAG 检索恒为空、AI 只答「知识库中没有相关内容」且全程无报错；另外它每次运行都会变，跟踪后每次 `git pull` 都会冲突。
  - 需要演示数据时不要提交库文件，改用 `python seed_practice_data.py`：可重复执行，且只清理并重建脚本自己写入的数据（`t_question.source='IMPORT'` 与 `t_learning_record.source='SYSTEM'`），不触碰真实用户行为。
- **Neo4j**：`KnowledgePoint` 节点（含 `kp_id` / `course_id` / `document_id` / `name` / `category` / `description` / `is_manual`），关系含 `document_id` / `confidence` / `is_manual` / `is_inferred`。
- **备份**：`backend/backup/`（`sqlite_20260905_145113.db` + `neo4j_20260905_145113.json` + kp_id 快照）。

## 7. 测试账号

引导账号在后端**首次启动时自动创建**（`ensure_default_teacher` / `ensure_default_admin`），口令按下面两种来源之一确定：

- **未配环境变量**（默认）：现场生成 16 位随机口令，**只在启动日志里打印一次**，同时置 `must_change_password=1` —— 首次登录会被强制跳转到改密页，改完才能进系统。
- **配了环境变量**：使用配置值，不强制改密（适合自动化/演示固定口令）。

| 账号 | 角色 | 可配的环境变量 | 备注 |
|---|---|---|---|
| `sysadmin` | 管理员 | `DEFAULT_ADMIN_USERNAME` / `DEFAULT_ADMIN_PASSWORD` | 管理员端入口 |
| `admin` | 教师 | `DEFAULT_TEACHER_PASSWORD` | **用户名固定为 `admin`，不读环境变量** |

学生账号通过 `/api/auth/register` 注册（默认 role=student）。

> ⚠️ **克隆后 `admin123` 是登不进去的**：上面两个账号的口令是随机生成的，请从后端启动日志里抄取。
> 只有**从旧版本升级上来的、且历史上已存在引导账号**的库，口令才仍是内置弱口令 `admin123`（后端每次启动都会打印安全提醒）。无论哪种情况，交付前都应通过「个人中心 → 修改密码」或管理员端「用户管理 → 重置密码」轮换。

## 8. 演示流程

1. 教师 `admin` 登录 → 创建课程 → 上传文档（选择已有课程，走 course_id，不自动建课）。
2. 文档解析 + LLM 抽取 → 图谱构建（Neo4j）。
3. 教师查看/编辑图谱（新增/改/删节点与关系，均按文档隔离）。
4. 学生登录 → 选课程 → 选文档 → Browse（图谱）/ Learning（掌握标记）/ Path（推荐）/ QA（RAG）/ Favorite。
5. 题库闭环：教师端「题库管理」新增题目（单选/多选/判断，可关联知识点）→ 学生端「做题练习」按文档/知识点出题 → 提交判分并看解析 → 错题本复习、收藏题目；教师端可查看每题作答正确率与题目收藏情况。
6. 重点演示：同一课程两个文档含同名知识点「数组」但上下文不同，图谱/学习/收藏/推荐/QA 互不串扰。

## 9. 已知技术债

1. 教师监测仍为课程级汇总（多文档课程无按文档视图）。
2. UNIQUE 保持 `(user_id, course_id, kp_id)`（未建四列唯一约束）。
3. `services/git_kg_manager.py` 为孤岛模块（`KnowledgeNode` 标签，独立实现）。
4. `services/relation_completion.py` 暂无 API（CLI 支持 `course_id + document_id`）。
5. `get_full_graph` 课程级/全局分支为 deprecated fallback（仅供 `/api/kg/*` legacy 入口）。
6. 同步阻塞 IO 跑在 async 端点内（**部分已修**：问答链路 `qa_service.ask()` 与 `api/qa.py`
   已改用 `asyncio.to_thread`，见 `docs/题库与推荐系统设计.md` §13.11；其余端点沿用现状，
   全量迁移 AsyncOpenAI 仍是更正确方向）。
7. `kg_manager` 关系类型 f-string 拼接存在 Cypher 注入风险（关系类型无法参数化）。
8. 上传接口 `file.filename` 直接拼路径（路径穿越风险，`MAX_UPLOAD_SIZE` 未强制）。
9. 题库为 Scope A（单选/多选/判断）自动判分：填空题、简答题未实现（判分准确性与成本风险，详见 `docs/题库功能说明.md`）。
10. 无选课/班级表 → 学生可见课程内全部启用题目（与文档、图谱可见性口径一致）；题库批量导入（Excel/CSV）与 AI 自动出题未实现（`t_question.source` 已预留 `AI` / `IMPORT`）。
11. 答题数据不写入 `t_learning_record`（避免污染学习进度口径），因此教学监测的进度统计仍只反映「掌握标记」，不含刷题行为。

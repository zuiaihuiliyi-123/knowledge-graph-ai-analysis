# 项目交付说明（Phase 10 收尾版）

> 基于 AIGC 的课程知识图谱智能构建与学习导航系统（A10 服务外包大赛）
> 数据模型：`Course → Document[] → KnowledgeGraph[] → KnowledgePoint[] → Relation[]`

---

## 1. 项目运行说明

- **后端**：FastAPI（`backend/`），统一响应 `{code, message, data, timestamp}`，JWT 鉴权。
- **前端**：Vue 3 + Vite 7 + Element Plus + AntV G6 + Pinia（`frontend-vue/`）。
- **图数据库**：Neo4j（本地实例，`KnowledgePoint` 节点 + 中英文关系类型 `PRECEDES/CONTAINS/RELATED_TO/APPLIES_TO`）。
- **关系库**：SQLite（`backend/data/app.db`，`t_` 前缀表；学习记录/收藏/向量三类文档级业务数据 + 课程/文档/用户元数据）。
- **RAG**：Embedding 走 SiliconFlow `BAAI/bge-m3`（OpenAI 兼容），LLM 走 DeepSeek `deepseek-chat`。

## 3. Neo4j 启动说明

- 本地 Neo4j（版本 2026.07.1，测试通过；**无 APOC 插件**）。
- 连接串：`bolt://localhost:7687`，用户 `neo4j`，密码见 `backend/.env` 的 `NEO4J_PASSWORD`。
- 首次启动后无需手工建约束；后端 `db.init_schema()` 幂等初始化。
- 注意：Neo4j 2026.x 拒绝旧 pattern-expression 语法（如 `NOT ()-[:PRED]->()`），必须用 `NOT EXISTS { MATCH ... }`（已在 `path_recommender.py` 修复）。

## 6. 数据库说明

- **SQLite**（`data/app.db`）：`t_user` / `t_course` / `t_document` / `t_kp_embedding` / `t_learning_record` / `t_student_favorite`。
  - 文档级业务表（embedding/learning/favorite）均含 `document_id`，UNIQUE 保持 `(user_id, course_id, kp_id)`（kp_id 全局唯一）。
  - `PRAGMA foreign_keys=ON`。
- **Neo4j**：`KnowledgePoint` 节点（含 `kp_id` / `course_id` / `document_id` / `name` / `category` / `description` / `is_manual`），关系含 `document_id` / `confidence` / `is_manual` / `is_inferred`。
- **备份**：`backend/backup/`（`sqlite_20260905_145113.db` + `neo4j_20260905_145113.json` + kp_id 快照）。

## 7. 测试账号

- 默认教师：`admin` / `admin123`（`ensure_default_teacher` 自动创建，仅演示用）。
- 学生账号通过 `/api/auth/register` 注册（默认 role=student）。

## 8. 演示流程

1. 教师 `admin` 登录 → 创建课程 → 上传文档（选择已有课程，走 course_id，不自动建课）。
2. 文档解析 + LLM 抽取 → 图谱构建（Neo4j）。
3. 教师查看/编辑图谱（新增/改/删节点与关系，均按文档隔离）。
4. 学生登录 → 选课程 → 选文档 → Browse（图谱）/ Learning（掌握标记）/ Path（推荐）/ QA（RAG）/ Favorite。
5. 重点演示：同一课程两个文档含同名知识点「数组」但上下文不同，图谱/学习/收藏/推荐/QA 互不串扰。

## 9. 已知技术债

1. 教师监测仍为课程级汇总（多文档课程无按文档视图）。
2. UNIQUE 保持 `(user_id, course_id, kp_id)`（未建四列唯一约束）。
3. `services/git_kg_manager.py` 为孤岛模块（`KnowledgeNode` 标签，独立实现）。
4. `services/relation_completion.py` 暂无 API（CLI 支持 `course_id + document_id`）。
5. `get_full_graph` 课程级/全局分支为 deprecated fallback（仅供 `/api/kg/*` legacy 入口）。
6. 同步阻塞 IO 跑在 async 端点内（沿用现状；迁移 AsyncOpenAI 是更正确方向）。
7. `kg_manager` 关系类型 f-string 拼接存在 Cypher 注入风险（关系类型无法参数化）。
8. 上传接口 `file.filename` 直接拼路径（路径穿越风险，`MAX_UPLOAD_SIZE` 未强制）。

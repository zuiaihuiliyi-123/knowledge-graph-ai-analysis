## 三、关系标注约定（33 条，均按决策树顺序判定）

| 类型 | 数量 | 触发句式 |
|------|:----:|----------|
| CONTAINS | 25 | "是一种 / 属于 / 包括 / 分为四种 / 常见类型有 / 其…操作" |
| APPLIES_TO | 3 | "基于…实现 / 用作 / 体现…逻辑" |
| RELATED_TO | 5 | "与…类似 / 工作原理一致 / 镜像对称 / 相较于 / 借助…实现（source 非方法类时）" |
| PRECEDES | **0** | 全章无"必须先学 A 才能学 B"的明确表述 |

每条关系均携带 `evidence`（原文逐字短句，已程序化校验全部逐字存在于测试文本中）与 `confidence`（0.65~0.95，反映证据强弱）。

### 决策树执行记录（两个敏感判定）

1. **`队列 → 广度优先遍历` 判为 RELATED_TO 而非 APPLIES_TO**：决策树第 3 步要求 source 为"方法/算法/技术"，队列在本文中类别为"概念"（数据结构），故降级为第 4 步 RELATED_TO（依据"广度优先遍历通常借助'队列'来实现……两者背后的思想是一致的"）
2. **`分治 → 二叉树`（APPLIES_TO，0.65）与 `二叉搜索树 → 多级索引`（APPLIES_TO，0.7）**：应用表述明确，但 source 类别为"方法"（分治）/数据结构（二叉搜索树视为技术类），证据强度中等，置信度如实调低

### PRECEDES 边界说明（重要）

文本中出现的以下表述**均未标为 PRECEDES**，按规则"文本先后≠前置、非明确必须不标"处理：

1. "在'二叉搜索树'章节中我们提到…"（AVL 节开头）——章节引用，说明教材顺序，但未声明"必须先学"
2. "回顾完全二叉树的定义…"（数组表示节）——复习指令，同上
3. "上一节介绍了链表表示下的二叉树的各项基本操作"——同章内引用，同上

**测试含义**：若模型在本文本上输出任何 PRECEDES 关系，均计为误报（严格匹配下 Precision 直接受损）。如团队认为章节引用应当计入 PRECEDES，可将上述第 1、3 条以"二叉搜索树 → AVL 树""二叉树 → 数组表示"补入 gold，并在此说明中登记。

### CONTAINS 中的两个敏感判定

- `完全二叉树 CONTAINS 完美二叉树`：依据"请注意，完美二叉树也是一棵完全二叉树"
- `二叉树 CONTAINS 二叉搜索树` **未标**：正文只说"常见的二叉树类型有完美/完全/完满/平衡二叉树"，未把二叉搜索树列入二叉树类型；虽有"AVL 树既是二叉搜索树"等间接证据，按"宁可漏标"原则不标

- 文本文件：`第7章_树.txt` → 喂给 `chunk_text_for_llm(max_tokens=3000)` 得到 3 个 chunk

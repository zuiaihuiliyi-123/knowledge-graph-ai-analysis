## 〇、金标准独立性纪律（最重要的一条）

**标注只依据原文，不得参考模型抽取结果。** 模型预测文件已封存，标注完成并冻结（记录 SHA256）之后才解封评分。若标注过程参考了预测，金标准会向模型偏移，"准确率达标"的结论将失去意义。

## 二、实体标注约定（与树章节完全一致）

1. 类别仅用四种：**概念 / 定理 / 公式 / 方法**；无法归类时用「概念」
2. 每个实体含 `description`：一句话、基于原文含义、不引入原文外的知识
3. 粒度要求："独立可学习的知识点"——不过度拆分（如"时间复杂度"与"最坏时间复杂度"若原文不作区分则只标前者），也不堆砌修饰
4. 不抽取：人名、页码、章节标题、指代词、仅一句带过的普通名词
5. 同义归一化：原文明确"也称/即"的同义写法，标注规范名，把变体记下来随 gold 提交（如树章"满二叉树 → 完美二叉树"的先例）；全角转半角、空白折叠、英文缩写统一大写由评测器自动处理，无需手工统一

## 三、关系标注约定（按决策树顺序判定，顺序不可跳级）

对任意两个已标注实体按下述顺序判定关系：

1. **上下位/整体-部分/类别-成员 → CONTAINS**（source 是上位概念/整体/类别，如"二叉树 CONTAINS 完美二叉树"）
2. 否则，文本明确表达"学习 source 是理解 target 的必要前提" → **PRECEDES**
3. 否则，source 是方法/算法/技术且文本明确说明其用于解决 target 代表的问题/对象 → **APPLIES_TO**
4. 否则，文本明确说明二者存在密切关联 → **RELATED_TO**
5. 以上均不满足 → 不标关系

每条关系的字段要求：

- `evidence`：支持该关系的**原文逐字短句**（评测器会程序化校验逐字存在于文本中）
- `confidence`：0.65~0.95，如实反映证据强弱（明确句式高、间接表述低）
- `core`：**true** = 文本明确、无争议、按决策树必然成立；**false** = 合理但边界模糊（Full 集）。宁可少标 core，不要放宽标准
- 方向：CONTAINS 上位 → 下位；PRECEDES 先学 → 后学；APPLIES_TO 方法 → 对象

## 四、标注流程

1. 通读原文（1 遍）
2. 打开对应模板 json，复制模板行逐条填写 `entities` 与 `relations`
3. 全部标注完成后运行 `backend/scripts/validate_gold.py`（若有）或由评测同学校验 evidence 逐字性
4. 提交 gold json，评测同学记录 SHA256 冻结

标注中出现难以判定的条目，在文件中随 gold 附一条备注（判定理由），作为决策树执行记录，供评测同学复核与写进报告。

# 知识抽取准确率评测报告 ——《Hello 算法》第7章「树」

> 配套：`eval_accuracy_live.py`（实时抽取评测）、`gold_第7章_树.json`（金标准）、`eval_report_第7章_树.json` / `_normalized.json`（完整结果）
> 本报告为真实章节规模（15330 字符 / 3 分块）的**初测基线**，定位三类系统性问题，供下一轮 Prompt 修复与复测参照。

## 一、测试设置

- 金标准：49 实体（概念 29 / 方法 18 / 公式 1 / 定理 1）、33 关系（CONTAINS 25 / RELATED_TO 5 / APPLIES_TO 3 / PRECEDES 0）
- 模型：deepseek-chat，temperature=0.15，3 轮独立运行；长文自动分块（6000 tokens + 400 overlap）+ 并发抽取 + 合并去重
- 指标：实体 P/R/F1；关系严格（source/type/target 全等）与宽松（节点对）P/R/F1

## 二、结果

## 三、误报/漏报归因（3 轮合计）

| 类别 | 误报 FP | 漏报 FN | 说明 |
|------|:------:|:------:|------|
| 纯臆造（节点对不在 gold） | 118 | — | 最大问题源，见下 |
| 方向颠倒 | 30 | 28 | "AVL 树既是二叉搜索树"被写成 `AVL 树 CONTAINS 二叉搜索树`（应为反向） |
| 节点对正确、类型判错 | 25 | 3 | 主要是 CONTAINS ↔ APPLIES_TO 混淆 |
| 方向+类型都错 | — | 7 | |
| 完全漏抽 | — | 36 | 部分因实体漏抽（分治、多级索引、红黑树、非线性数据结构等 10 个实体未召回） |

## 四、根因定位

1. **方向倒置（系统性）**：Prompt 只给了「X 是 Y 的一种 → Y CONTAINS X」的例子，未覆盖「X 既是 Y 又是 Z」句式。模型对"既是"句按"X 拥有 Y 的性质"反推成 X→Y。典型：`AVL 树 -[CONTAINS]-> 二叉搜索树/平衡二叉树`（3 轮全错）。
2. **APPLIES_TO 过度生成**：模型 3 轮平均输出 22 条 APPLIES_TO（gold 仅 3 条），把"在 X 中进行的操作"（如 `中序遍历 -[APPLIES_TO]-> 二叉搜索树`）都当成应用关系，违反决策树第 3 步"source 是方法/算法/技术，用于解决 target 代表的问题/对象"中的"解决"要求。
3. **CONTAINS 的"整体-部分"泛化过宽**：如 `AVL 树 CONTAINS 平衡因子/高度/旋转操作`。部分属金标准粒度选择（我们只标了"分为四种"这类明确包含），部分属模型将"组成部分"与"子知识点"混同。
4. **实体漏召回**：`分治`、`多级索引`、`红黑树`、`非线性数据结构`、`失衡节点` 等 10 个实体未召回，其中多数出现在小节末尾的"典型应用/效率"段落——模型对"应用场景"段落的实体抽取偏弱。

## 五、修复建议（下一轮迭代）

1. **Prompt 补方向例**：加正反例 ——「AVL 树既是二叉搜索树，也是平衡二叉树」→ `二叉搜索树 CONTAINS AVL 树`、`平衡二叉树 CONTAINS AVL 树`（严禁反向）；"既是…也是…"句式中主语是 target。
2. **收紧 APPLIES_TO**：要求 target 必须代表"问题/应用场景/对象"，若 target 本身是课程知识点（如中序遍历、递归），不得用 APPLIES_TO，改用 RELATED_TO 或不输出。
3. **收紧 CONTAINS 整体-部分**：限定为"文本明确列出成员/类型清单"（"分为/包括/类型有/属于"）时使用，单纯"组成部分"不标。
4. **实体召回**：在实体要求中补充"出现在'典型应用''常见应用'段落中的概念同样属于知识点实体"。
5. 复测目标：实体 F1 ≥ 0.9、关系严格 F1 ≥ 0.4（宽松 F1 ≥ 0.6），PRECEDES 误报保持 0。

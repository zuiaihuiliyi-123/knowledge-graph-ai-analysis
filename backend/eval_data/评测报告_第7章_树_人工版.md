## 三、问题定位（基于模型输出逐条检查）

### 问题 1（最严重）：CONTAINS 方向系统性颠倒

14/17 条 gold 关系 3 轮全部漏报，主因是模型把"属于"方向写反。第 3 轮实际输出：

| 模型输出（错误） | 应为（gold） |
|---|---|
| 完美二叉树 -[CONTAINS]-> 完全二叉树 | 完全二叉树 -[CONTAINS]-> 完美二叉树 |
| 层序遍历 -[CONTAINS]-> 广度优先遍历 | 广度优先遍历 -[CONTAINS]-> 层序遍历 |
| 前/中/后序遍历 -[CONTAINS]-> 深度优先遍历 | 深度优先遍历 -[CONTAINS]-> 前/中/后序遍历 |
| AVL树 -[CONTAINS]-> 二叉搜索树 | 二叉搜索树 -[CONTAINS]-> AVL 树 |
| AVL树 -[CONTAINS]-> 右旋/左旋/…（连源节点都换成了 AVL树） | 旋转 -[CONTAINS]-> 四种旋转 |

**根因**：Prompt 中"source 是上位概念"的方向约定，与模型对"X 属于 Y"的自然语感（X→Y）冲突。"栈是一种操作受限的线性表"例子里主语恰好是上位词（线性表），掩盖了"成员作主语"时的方向问题（如"完美二叉树**也是**一棵完全二叉树""**都属于**深度优先遍历"）。

### 问题 2：Q&A 段落污染

模型把「Q & A」问答内容当作知识来源，输出荒谬关系：
- `满二叉树 -[CONTAINS]-> 底层节点数量`、`节点总数 -[CONTAINS]-> 满二叉树`、`广度优先遍历 -[APPLIES_TO]-> 满二叉树`（均来自 Q&A 中"队列节点数量是 2^h 吗"的问答）

**建议**：测试文本剔除 Q&A 段落，或在 Prompt 中声明"问答体内容不作为知识来源"。

### 问题 3：APPLIES_TO 方向与目标错误

- `深度优先遍历 -[APPLIES_TO]-> 递归`（应为 递归 APPLIES_TO 深度优先遍历）
- `广度优先遍历 -[APPLIES_TO]-> 队列`（方向反；且 target 是知识点而非应用场景）

### 问题 4：普通名词被抽成实体

`时间复杂度`、`节点总数`、`底层节点数量` 等被抽为实体，拉低实体精确率（74%）。Prompt 已有"不要抽取普通名词"，但缺具体反例。

## 四、修复建议（按优先级）

1. **重写 CONTAINS 方向规则**：改为"Y 包含 X / X 是 Y 的一种 / X 属于 Y / X 也是 Y → **Y CONTAINS X**，方向永远从'类/整体'指向'成员'；'既是…也是…''本质上属于''都属于'等句式的主语是成员，位于 target"。附 3 组正反例（含"完美二叉树也是一棵完全二叉树"）。
2. **过滤问答体**：测试文本删除 Q&A 段落（约 20 行），并保留"Q&A 不是知识来源"的 Prompt 声明。
3. **APPLIES_TO 收紧方向与目标**：明确"source=方法，target=被解决的问题/应用场景，且 target 不得是课程知识点本身"。
4. **普通名词反例**：补充"时间复杂度、节点总数、数据、数组等不是知识点"。
5. 复测目标：实体 F1 ≥ 0.85、关系严格 F1 ≥ 0.4、宽松 F1 ≥ 0.6、PRECEDES 保持 0 误报。

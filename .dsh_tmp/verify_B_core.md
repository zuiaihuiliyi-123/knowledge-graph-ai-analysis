## 5. 第 8 章 学习路径（P79–89）

### 5.1 前置关系模型 / 三类推荐 / 降级
- 【方案】P80–85 §8.1–8.4：PRECEDES `A→B` 表示 A 是 B 前置；入边=前置、出边=后继、无入边=根；BFS 1–5 级、反向 DFS 1–10、最多 5 条路径、CONTAINS 上层概念降级、RELATED_TO 相关概念降级、topK=10、allowed_ids 收敛。
- 【实际】`backend/app/services/path_recommender.py`：
  - 前置：`:120` `MATCH path = (prereq)-[:PRECEDES*1..5]->(target)`，`:123` `length(path) AS depth`，`ORDER BY depth`；
  - 降级：`:144` `(parent)-[:CONTAINS]->(target)`，reason「建议先了解的上层概念」；
  - 下一步：`:175-186` 空掌握→根节点 `LIMIT 10`；`:205-255` 全量前置校验 + `LIMIT 10`；
  - 目标路径：`:298` `(start)-[:PRECEDES*1..10]->(target)` + `NOT EXISTS` 根判定，`ORDER BY path_length LIMIT 5`；降级 `:337` `RELATED_TO`。
- **结论：功能语义一致，但「算法实现描述」不符（重要）**：
  - 方案 P82–85 Algorithm 9/11 把实现写成应用层「层序 BFS 逐级展开 + `seen` 去重」「自目标反向 DFS 递归」；
  - 实际是 **Neo4j 变长路径匹配**，没有手写 BFS/DFS，也没有 `seen` 去重。Algorithm 9 声称「`seen` 保证环形图不会无限递归 / depth 天然等于最短前置距离」，而变长路径会返回**同一前置经多条路径的多行**，`depth` 是各条路径长度而非该节点的最短距离——若图谱里存在 A→B→C 与 A→C 两条路径，A 在结果里会出现两次（depth 1 与 2）。
- 【改法】把 Algorithm 9/11 改成「Cypher 变长路径 + 应用层排序/截断」的真实写法，或明确写「工程上用 Neo4j `PRECEDES*1..D` 等价实现 BFS 语义」；删除「`seen` 去重」与「depth=最短距离」的强断言。答辩若被要求在白板画 BFS，按现在的描述会与代码对不上。

### 5.2 与题库联动

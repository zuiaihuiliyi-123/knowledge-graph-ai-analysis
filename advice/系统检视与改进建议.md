## 一、总体结论

**功能完整度和演示链路都不错，但当前状态更像"能演示"而不是"能上线"。**

系统的主链路——文档上传 → 解析 → LLM 抽取 → Neo4j 入图 → 图谱可视化 / RAG 问答 / 学习路径 / 题库练习 / 教师监测 / 管理员治理——是完整可演示的，批量上传、阅读器、成员权限、题库批改等细节也能看出投入。最该优先处理的不是界面美观，而是三类问题：

1. **安全默认值与权限缺口**：源码内含真实 Neo4j 口令、JWT 密钥有公开默认值、任何人可注册为教师、练习接口缺少课程级鉴权、JWT 无法吊销。
2. **长任务与会话状态不保**：文档抽取离开页面即失去进度；401 静默踢出；编辑知识点、做练习、AI 对话在导航后全部丢失。
3. **维护成本**：`StudentView.vue` 4048 行、`TeacherView.vue` 4531 行；仓库内还有 9 个被 git 跟踪的备份/游离文件；几乎没有 lint、类型检查、单测和可用的 CI。

如果只做三件事，建议选：**P0 的密钥 / 注册 / 练习鉴权**、**邀请与登录回跳**、**上传任务中心**——它们分别决定"会不会被打穿""新人能不能进来""教师敢不敢用"。

## 二、做得好的地方

以下设计建议保留，不要在后继重构中丢掉：

- **课程成员三档权限模型**：创建者 / 协作教师 / 已通过学生成员，配合 `Permissions.resolve()` 明确区分"读元数据 / 读内容 / 管理"，文档级与课程级隔离做得成体系。
- **批量上传的容错**：真实进度、失败重试、刷新后按"文件名 + 字节数"认领占位行，避免同一文档出现两行；单个文件失败不影响同批其他文件。
- **阅读器体验**：续读提示、`Ctrl+F` / `F3`、`Esc` 分层退出、输入法 Enter 保护、PDF/DOCX/TXT/MD 多格式在线预览。
- **XSS 防护**：`frontend-vue/src/utils/markdown.js` 先整体转义再解析 Markdown，链接协议白名单，做法正确。
- **删除确认**：删除课程、文档、节点、关系、成员均有二次确认。
- **数据库迁移**：SQLite 重建表迁移使用 `BEGIN IMMEDIATE`、行数校验、`foreign_key_check`、失败回滚，是仓库里做得最扎实的部分之一。
- **评测与文档**：知识抽取准确率报告、问答测试集、Prompt 工程记录、论文算法复现实验等文档齐全，评测脚本只读、结果落 JSON。

## 三、P0：上线前必须处理的安全与正确性问题

### 3.1 源码中有真实 Neo4j 口令，SECRET_KEY 是可公开猜到的默认值

**证据**

- `backend/app/core/config.py:42`
  ```python
  # 历史问题：这里曾内置真实图库口令（已移除，本文不重复口令本体）
  NEO4J_PASSWORD: str = os.getenv("NEO4J_PASSWORD", "<历史内置口令，已移除>")
  ```
- `backend/app/core/config.py:66`
  ```python
  SECRET_KEY: str = os.getenv("SECRET_KEY", "please-set-a-random-secret-key-of-at-least-32-bytes")
  ```
- `backend/.env.example:26` 将 `SECRET_KEY` 注释掉，照模板复制 `.env` 后不会设置。
- `backend/app/main.py:19-25` 的启动生命周期不做任何密钥校验。

**影响**

- 任何拿到仓库或历史副本的人都获得图库凭据；未配置环境变量的新部署会直接连到同一个口令。
- 忘记配置 `SECRET_KEY` 时，任何人可用公开字符串签发任意角色的 JWT；`require_teacher` 只看 JWT 里的 `role`（`backend/app/core/dependencies.py:50-54`），因此可伪造教师 token 调用全平台数据接口。
- 该口令已随 git 历史存在，应视为已泄露。

**建议**

- 两个密钥改为"缺失即启动失败"或至少启动时输出醒目警告；`.env.example` 中标为必填并说明生成方式。
- 立即轮换 Neo4j 口令；`SECRET_KEY` 用 `secrets.token_urlsafe(48)` 生成。
- 如仓库已公开，考虑用 `git filter-repo` 清理历史，或在部署侧限制 Neo4j 来源 IP。

### 3.2 任何人都能注册成教师，登录页硬编码管理员演示账号

**证据**

- `backend/app/api/auth.py:59-78`：注册接口直接接受 `role in ("teacher", "student")`，无邀请、无审核、无管理员确认。
- `backend/app/api/auth.py:62-64`：密码只校验非空，长度和强度仅由前端约束。
- `frontend-vue/src/views/LoginView.vue:91-93`：硬编码 `demo_teacher / demo_student / demo_admin`，密码均为 `demo123456`。
- 本地 `backend/data/app.db` 中确实存在 `demo_admin` 管理员账号。

**影响**

- 匿名用户注册为教师后即可创建课程、上传文档（触发 LLM 计费）、调用所有 `require_teacher` 接口。
- 叠加 3.5 节的 `/api/kg/all`，等于任意人可导出全平台知识图谱。
- 演示账号随截图、文档、视频扩散后，管理员口令就是公开的；若演示库被部署到公网，风险更高。

**建议**

- 公开注册只允许 `student`；教师账号由管理员创建、邀请码或审批流程授予。
- 演示账号仅在前端 `import.meta.env.DEV` 或显式 `VITE_DEMO=1` 时显示；发布包中删除或改密。
- 后端补密码强度校验，与前端规则保持一致。

### 3.3 练习接口完全没有课程权限校验，可越权获取任意题目答案

**证据**

- `backend/app/api/practice.py:59`（出题）、`:78`（推荐出题）、`:95`（提交作答）三个核心端点只 `Depends(get_current_user)`，没有调用 `Permissions`。
- `backend/app/services/question_service.py:1071`：`get_questions` 只校验课程是否存在，不校验成员关系。
- `backend/app/services/question_service.py:1180`：`submit` 只按 `question_id` 取题并判分，返回 `correct_answer` 和 `analysis`。
- `backend/app/services/question_service.py:1066` 的注释仍写"系统当前无选课关系表，故不做仅已选课程限制"——但 `t_course_member` 早已存在，这是漏改。

**影响**

- 任意登录用户可枚举 `question_id`，通过 `POST /api/v1/practice/submit` 拿到任意课程题目的答案与解析。
- `GET /api/v1/practice/questions?course_id=` 可直接列出任意课程题面。
- 可向不属于自己的课程写入答题记录，污染教师的教学监测统计。

**建议**

- `get_questions` / `recommend_questions` / `submit` / 收藏相关端点统一先调用
  `Permissions.require_course_content(question["course_id"], current_user)`。
- 出题与提交都校验题目所属课程；补一条越权回归测试。

### 3.4 账号禁用 / 改密后旧 JWT 仍有效，"强制改密"只在浏览器里拦

**证据**

- `backend/app/core/dependencies.py:24-47`：`get_current_user` 只验签、不查库。
- `backend/app/core/dependencies.py:57-77`：只有 `require_admin` 回查用户状态，普通用户不复核。
- 全项目没有 logout、jti、token 版本号；`grep` 无命中。
- `backend/app/api/auth.py:131`：`must_change_password` 只写进登录响应，由前端路由守卫引导；直接带 token 调 API 可绕过。
- `backend/app/api/auth.py:53`：JWT 有效期 24 小时，无 refresh 机制。

**影响**

- 管理员"注销 / 降级 / 重置密码"后，旧 token 在 24 小时内仍可读写所有非管理端接口。
- 被停用的学生仍可继续答题、问答；被降级的教师仍可创建课程、删文档、改图谱。
- 首次登录强制改密的引导可被绕过。

**建议**

- `t_user` 增加 `token_version`：签发时写入，`get_current_user` 每次比对；改密、禁用、角色变更时递增。
- 至少在 `get_current_user` 中回查一次 `is_active` 与 `role`（性能可接受，SQLite 单行查询）。
- `must_change_password=1` 时后端只放行改密与登出接口。
- 补 `POST /api/auth/logout`（前端清 token + 服务端递增版本号）。

### 3.5 任何教师都能导出全平台图谱，CORS 还是通配

**证据**

- `backend/app/api/knowledge_graph.py:19-24`：`/api/kg/all`、`/api/kg/stats` 仅 `Depends(require_teacher)`，`kg_manager.get_graph_data()` 无任何参数。
- `backend/app/core/database.py:183-188` 的 Cypher 为 `MATCH (n:KnowledgePoint) OPTIONAL MATCH ...`，没有 `course_id` 条件。
- `backend/app/main.py:57-63`：
  ```python
  allow_origins=["*"],
  allow_credentials=True,
  allow_methods=["*"],
  allow_headers=["*"],
  ```

**影响**

- 任意教师（叠加 3.2 即任意匿名用户）可一次拿到所有课程的知识点名称、类别、描述与全部关系边；返回体无分页/上限，大库时还会拖垮进程。
- 通配 CORS 允许任意站点跨域调用 API；`*` 与 `allow_credentials=True` 本身也不符合规范，未来改用 Cookie 认证会立即出错。

**建议**

- `/api/kg/all`、`/api/kg/stats` 下线，或改为管理员专用并强制 `course_id` + 分页。
- CORS 从环境变量读取允许来源白名单（开发 `http://localhost:5173`，生产前端域名）；不使用 Cookie 时关闭 `allow_credentials`。

### 3.6 上传与部署健壮性

**证据与问题**

1. **上传先全量读入内存再判大小**
   - `backend/app/api/documents.py:40`：`content = await file.read()`
   - `backend/app/services/document_service.py:123` 才检查 `MAX_UPLOAD_SIZE`（50MB）
   - `backend/app/api/profile.py:63` 头像同样先读再判 2MB
   - 并发大文件请求可在判大小前耗尽内存。应流式写入临时文件，边写边累计字节数，超限即中止。
2. **Neo4j 约束与索引从未在应用启动时初始化**
   - `backend/app/core/database.py:75-102` 定义了 `init_schema()`（`kp_id` 唯一约束、课程/文档/名称索引）。
   - `backend/app/main.py:19-25` 的 `lifespan` 只调用 SQLite 初始化，**没有调用 `db.init_schema()`**；全仓库仅测试与迁移脚本调用。
   - `README.md` 却写"启动后由后端幂等初始化约束"。
   - 新部署的图库没有索引，`MERGE (kp:KnowledgePoint {course_id, document_id, name})` 每次插入做全图扫描，长文档入库呈 O(N²)；`kp_id` 唯一约束缺失也失去并发去重兜底。
3. **`/health` 不检查依赖**
   - `backend/app/main.py:98-101` 永远返回 `{"status": "ok"}`。
   - 登录页据此显示"后端在线"，Neo4j 宕机时用户看到在线但所有图谱功能失败。

**建议**

- 上传改流式落盘，按 `UploadFile.file` 分块读取并累计大小；批量文件数设上限；用真实文件类型（魔数）校验，不只信扩展名。
- `lifespan` 中调用 `db.init_schema()`，失败记明确日志；把索引初始化纳入健康检查。
- `/health` 区分 `liveness` 与 `readiness`：后者检查 SQLite 与 Neo4j 连通性。

### 3.7 其他安全缺口

- **无速率限制、无登录锁定**：`backend/app/api/auth.py:82-97` 登录无失败计数；注册无频率限制；`backend/app/main.py:36-62` 无任何限流中间件；`question_service.py:1190` 同一题可无限重复提交。可暴力破解弱口令、批量注册垃圾账号、刷爆答题记录表、无限调用上游 LLM。
- **内部异常直接透给用户**：`backend/app/services/qa_service.py:364` 把 `str(e)` 拼进回答；`backend/app/api/graph.py:93-94` 把 Neo4j 异常拼进响应；`document_service.py:198-242` 把异常写进 `error_message` 并返回给所有课程成员。会暴露上游 API 地址、模型名、服务器路径。
- **审计 IP 可伪造**：`backend/app/services/admin_service.py:54-72` 无条件信任客户端 `X-Forwarded-For`。
- **JWT 未强制 `exp`**：`backend/app/core/dependencies.py:31` 的 `jwt.decode` 没有 `options={"require": ["exp"]}`；正常登录会带 `exp`，但脚本或历史 token 可能没有。
- **PBKDF2 迭代次数偏低**：`backend/app/core/security.py:12` 为 `100_000`，OWASP 对 PBKDF2-SHA256 建议约 600k；建议升级 Argon2id 或渐进式 rehash。

## 四、P1：用户体验问题（按真实使用路径）

### 4.1 登录 / 注册 / 邀请——新人第一步就断

**① 邀请链接对新用户是断的**

- `frontend-vue/src/router/index.js:65-69`：`/invite/:token` 没有 `meta.public`，未登录打开会被守卫送去登录。
- `frontend-vue/src/views/LoginView.vue:106-123`：`handleLogin` 成功后固定 `router.push('/course-center')`，完全不读 `route.query.redirect`。
- `frontend-vue/src/views/RegisterView.vue` 注册成功后同样直接跳课程中心。

> 用户感受：受邀学生"点链接 → 登录 → 进了一个和邀请无关的页面"，会判断邀请失效，教师需重新发链接。

**② 登录页"加课码 / 邀请链接"按钮是死链**

- `frontend-vue/src/views/LoginView.vue:61`：`router.push('/invite')`
- 路由表只有 `/invite/:token`，且没有 catch-all 404 页（`router/index.js` 中无 `pathMatch`）。
- 点击后无反应或被打回登录页，用户以为按钮坏了。

**③ 401 静默踢出，页面和未提交内容全部丢失**

- `frontend-vue/src/api/request.js:39-45`：401 时清 token 后 `window.location.href = '/login'`，无提示、无 `redirect`、无草稿保护。
- 教师正在编辑知识点、学生正在做第 9 题时突然回登录页，状态全部销毁。

**④ 首屏先闪"后端服务未连接"的红色错误，还展示开发命令**

- `LoginView.vue:64-67`、`RegisterView.vue:73-76`：只看 `backendOnline`，初始 false；健康检查要 3 秒超时，期间就显示红字。
- `stores/app.js:45-47` 已有 `healthChecking` 状态，但未被登录页使用。
- `components/BackendStatusCard.vue:25-31`：离线时直接把 `python -m uvicorn app.main:app --reload` 展示给终端用户。

**⑤ 没有"忘记密码"入口**

- 登录页只有注册/邀请入口；修改密码必须输入原密码；只有管理员能重置。
- 学生锁死只能线下找管理员，演示现场极易卡住。

**建议**

- 邀请页设为公开页：未登录先展示课程信息，点"接受"再登录并回到 token；或登录/注册成功后读取并校验站内 `redirect` 回跳。
- 登录页按钮指向 `/course-center?tab=join`；补 404 页面。
- 401 先 `ElMessage.warning`，再用 router 跳转并携带当前 `fullPath`；关键编辑页接草稿保护。
- 健康状态改为三态（检测中 / 在线 / 离线），命令只在 DEV 下显示。
- 至少提供"忘记密码请联系管理员"的说明入口，有条件再加邮箱/学号重置。

### 4.2 教师端

**① 上传 / 抽取长任务，一切 Tab 就失联**

- `frontend-vue/src/views/TeacherView.vue:1861-1874`：轮询定时器里有 `activeTab.value !== 'documents'` 就停止。
- `TeacherView.vue:1920-1933`：完成/失败 toast 在轮询函数内部，切走后再也收不到。
- `TeacherView.vue:1830-1831`：`DOC_POLL_TIMEOUT = 30 * 60 * 1000`，注释写"10 分钟兜底"，常量与文案不一致。
- 教师一次上传 20 份资料后去出题，不知道哪篇完成、哪篇失败，几十分钟后回来才发现，甚至重复上传。

**建议**：把任务轮询提升到全局 store / 任务中心；侧栏显示"处理中 N / 完成 N / 失败 N"徽标；完成时用 `ElNotification` 或浏览器通知；提供"取消跟踪"；修正超时常量与文案。

**② 数据总览的"上传课程资料"快捷入口点错页**

- `frontend-vue/src/views/DashboardView.vue:190`：指向 `/teacher?tab=upload`
- `frontend-vue/src/views/TeacherView.vue:1657`：`TEACHER_TABS` 没有 `upload`
- `TeacherView.vue:2938-2940`：未知 tab 静默回落到 `courses`

> 用户点"上传课程资料"却停在课程列表，以为按钮坏了。改为 `?tab=documents`；未知 tab 应提示而不是静默回落。

**③ 编辑知识点时切节点，静默丢弃未保存内容**

- `TeacherView.vue:2275-2294`：`watch(selectedNode)` 直接用新节点覆盖 `editForm`，没有 dirty 比对。
- 全项目没有任何 `onBeforeRouteLeave` / `beforeunload` / `before-close`（`grep` 为 0）。

## 五、P2：性能与成本

### 5.1 同步阻塞调用跑在 async 路由里

**证据**：`app/api/` 下 110+ 个 `async def`，只有问答与文档上传链路显式使用 `asyncio.to_thread`（`qa_service.py:336`、`document_service.py:196/237`）。其余如：

- `api/courses.py:139-154` → `CourseService.get_course_detail` → `db.query`
- `api/dashboard.py:14-22` → 每次 5 轮全图扫描
- `api/questions.py:210-225` → `auto_label` → `embedder.embed` 外部 HTTP
- `question_service.py:940`：`await DocumentParser.parse(path)` 直接 await 同步 PDF/DOCX 解析
- `openai` 同步客户端、Neo4j 同步驱动、文件读写都在事件循环里

**影响**：一个学生的慢问答、一个教师的自动标注、一次 Neo4j 超时，会阻塞同进程内所有请求；单 worker 下并发退化为串行。

**建议**：不需要 `await` 的端点改为普通 `def`（Starlette 自动丢线程池）；或统一 `asyncio.to_thread`；为 LLM/embedding 配置有界线程池与信号量。

### 5.2 全图扫描与聚合

- `backend/app/services/dashboard_service.py:63-114`：每次数据总览做 5 次全图扫描（节点总数、关系总数、概念数、类别分布、关系类型分布），无 `course_id` 条件，`except Exception: pass` 把故障伪装成 0。
- `backend/app/services/course_service.py:127-138`：每次课程列表做 2 次全图聚合（节点数、关系数），同样无 `course_id` 条件。
- 建议：改为按 `course_id IN $ids` 的单次 `GROUP BY`，结果加 TTL 缓存；故障时返回明确错误而不是 0。

### 5.3 N+1 查询

- `backend/app/services/teacher_service.py:60`：每个学生调用一次 `PathRecommender.recommend_next`；`path_recommender.py:213-228` 又对每个候选查一次前置关系 → 每学生最多约 11 次 Neo4j 往返。
- `question_service.py:1229`：每条答题记录 `get_question`，最多 500 条 = 500 次独立 SQLite 连接。
- `question_service.py:1363`：每个收藏再查一次题目。
- `grading_service.py:199-220`：批量批改每条记录查 3 次（答题记录、题目、课程+成员）。
- `sql_database.py:736-745`：每次查询新建 SQLite 连接，无连接复用。
- 建议：批量查询（`question_id IN (...)`、一次 `GROUP BY`）、教师监测改成一次 Cypher 计算全班、SQLite 引入线程本地连接复用。

### 5.4 LLM / Embedding 调用

- `embedding.py:44`：`self.client.embeddings.create(...)` 未传 `timeout`，会落到 SDK 默认约 600 秒。
- `knowledge_extractor.py:436-444`：失败分块串行重试一次，无指数退避/抖动；`455-464` 单块 60s。
- `qa_service.py:350-361`：只有 chat 用了 `timeout=settings.QA_TIMEOUT`（15s），无 SSE 流式。
- `api/qa.py:51-59`：一次性返回 JSON，学生 15 秒内无任何输出。
- 建议：给所有 OpenAI client 设置显式 `timeout` / `max_retries`；重试加 backoff + jitter；加入全局并发上限与熔断；QA 迁移到 `AsyncOpenAI` + `StreamingResponse`（SSE）。

### 5.5 向量索引与缓存

- 索引失效粒度是整个 `(course_id, document_id)`：教师改一个知识点描述 → 该文档全部向量删除 → 下次问答全量重算（真实外部 API 调用）。
- `vector_index.py:83` 的 `_cache` 无容量上限、无过期淘汰，每个新文档常驻一份矩阵，内存持续增长。
- 懒重建本身是对的；建议按 `kp_id` 做增量更新，并把缓存改为有界 LRU（按条目数/总字节）。

### 5.6 前端首屏体积

- `frontend-vue/src/router/index.js:2-4` 静态导入 `TeacherView` / `StudentView`，两个 4000+ 行页面把 ECharts / G6 / Element Plus 全带进首屏。
- `src/main.js:3-5` 全量注册 Element Plus 并引入完整 CSS。
- `TeacherView.vue:1629`、`DashboardView.vue:122` 使用 `import * as echarts`。
- 实测：入口 chunk 约 1.38MB JS + 482KB CSS；`vendor-g6` 1.41MB；`vendor-element` 938KB；初始路由合计约 4.3MB（gzip 约 1.27MB）。
- 建议：路由改为 `() => import(...)`（2 行改动）；ECharts 用 `echarts/core` + 按需图表；Element Plus 用 `unplugin-auto-import` / `unplugin-vue-components`；`GraphCanvas` 用 `defineAsyncComponent`。

### 5.7 监控指标与错误语义

- `backend/app/main.py:47-51`：用 `request.url.path` 作为指标 key，`/documents/123` 每个 id 一个桶，`core/metrics.py:51` 的 `defaultdict` 永不清理、无上限。
- `core/metrics.py:57`：只把 HTTP `>=400` 计为错误；但业务错误全部返回 HTTP 200（`core/response.py:17-19`，路由直接 `return error(...)`）。
- 影响：管理端"错误率"几乎恒为 0；长跑进程内存随 URL 数增长；无法区分"空课程"和"图库故障"。
- 建议：用路由模板 `request.scope["route"].path` 替代原始 path，设最大 key 数；业务错误映射为 4xx 或按 `code` 单独计数；配置结构化日志与 request id。

### 5.8 其他

- `api/admin.py:81-82`：管理员筛选器课程下拉硬编码 `page_size=500`，超过 500 门的平台会静默缺项。
- 列表接口普遍缺分页：`GET /api/v1/documents?course_id=` 返回全部文档；`PracticeService.records` 先全量读再切片。
- `core/database.py:71-73`：所有 Neo4j 异常都触发 30 秒熔断，Cypher 语法错或约束冲突也会让全站图查询停摆；应只对连接类异常熔断。
- `main.py:19-25`：lifespan 结束未调用 `db.close()`，`--reload` 或重启时连接需等进程退出才释放。

## 七、产品层面值得加的几条

1. **知识融合下放给教师**
   - 现状：同名知识点按 `(course_id, document_id, name)` 独立，跨章节天然分裂；只有管理员端能做候选扫描/合并。
   - 建议：教师端增加"本课程重复知识点"入口，支持一键合并/别名；投入小、感知强。

2. **课程级知识图谱**
   - 现状：学生必须选文档才能看图谱、问 AI，看不到整门课的知识结构。
   - 建议：课程级聚合视图（文档用颜色/分组区分），既贴合"课程知识图谱"的赛题定位，也能支撑课程级学习路径。

3. **学习路径可纠错**
   - 现状：推荐完全依赖抽取出的 `PRECEDES` 边，抽错就推荐错。
   - 建议：加"这个前置关系不对"的反馈按钮；教师端提供路径审核/编辑。

4. **回收站 / 撤销**
   - 现状：删除课程、文档、题目、知识点均无撤销，误删只能找管理员从 `backup` 恢复。
   - 建议：软删除 + 30 天回收站；前端删除 toast 加"撤销"。

5. **演示与部署友好**
   - 一键重置演示数据（比赛现场很实用）；
   - `/health` 显示 SQLite / Neo4j / LLM 各依赖状态；
   - Docker Compose 一键起（Neo4j + backend + frontend）。

6. **通知与待办中心**
   - 教师：待批改数量、抽取失败、成员申请；
   - 学生：申请结果、新题推荐、学习提醒。
   - 目前这些信息散落在各页面，没有一个汇总入口。

## 九、已核实无问题的点

为避免后续排查走弯路，以下事项已核查，**不是**问题：

- **SQL 注入**：手写 SQL 全部使用 `?` 参数化；动态列名来自白名单（`sql_database.py:3383-3389`、`:3545`、`:3764`）；`WHERE` 拼接只拼固定片段。
- **上传路径穿越**：文件名经 `os.path.basename(filename.replace("\\", "/"))`（`document_service.py:76-78`），保存路径由服务端 `doc_id` 前缀拼接；头像文件名服务端生成。
- **管理员端点**：`api/admin.py` 与 `api/admin_fusion.py` 每个端点都显式 `Depends(require_admin)`，且 `require_admin` 回查数据库确认角色/启用状态。
- **SQLite 迁移**：重建表使用 `BEGIN IMMEDIATE` + 行数校验 + `foreign_key_check` + 失败回滚。
- **Markdown XSS**：`utils/markdown.js` 先整体转义再解析，链接协议白名单。
- **权限模型主体**：课程/文档/图谱/问答/学习记录/收藏等主要读取接口均已接入 `Permissions`；漏网的是练习模块与 `/api/kg/*` 遗留接口。
- **删除确认**：课程、文档、节点、关系、成员删除均有二次确认。
- **批量上传**：具备真实进度、失败重试、刷新后占位行认领，是项目里完成度较高的交互。

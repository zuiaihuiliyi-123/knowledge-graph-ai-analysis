### 2.2 认证与注册

**文件**：`backend/app/api/auth.py`、`backend/app/core/dependencies.py`

#### 2.2.1 教师自助注册默认关闭

- 新增公开接口 `GET /api/auth/registration-policy`，返回：
  ```json
  {
    "allow_teacher_self_register": false,
    "min_password_length": 6
  }
  ```
- `POST /api/auth/register`：
  - 用户名要求 3–20 字符；
  - 密码长度按 `MIN_PASSWORD_LENGTH` 校验；
  - 请求 `role=teacher` 且未开启 `ALLOW_TEACHER_SELF_REGISTER` 时返回业务码 `1003`：
    > 教师账号需由管理员创建或审批，当前不接受自助注册
- 如需比赛/演示环境恢复自助注册，在 `.env` 设置：
  ```env
  ALLOW_TEACHER_SELF_REGISTER=true
  ```

#### 2.2.2 JWT 可吊销（token_version）

- `t_user` 新增 `token_version INTEGER NOT NULL DEFAULT 0`。
- 签发的 JWT 增加 `ver` 声明。
- `get_current_user` 每次请求回查一次 `t_user`，校验：
  1. 用户仍存在；
  2. `is_active=1`；
  3. `token_version` 与 JWT 中的 `ver` 一致；
  4. 角色以数据库为准（防止降级后旧 token 继续使用）。
- 以下操作会递增 `token_version`，使旧 token 立即失效：
  - 用户本人改密（`update_password`）；
  - 管理员重置密码（复用 `update_password`）；
  - 管理员启用/禁用账号（`set_user_active`）；
  - 管理员修改角色（`set_user_role`）；
  - 用户自助注销（`deactivate_user`）；
  - 新增登出接口（`POST /api/auth/logout`）。
- 兼容性：旧 token 没有 `ver` 声明时按 `0` 处理；数据库迁移后历史用户 `token_version=0`，因此**升级不会把已登录用户全部踢下线**。只有发生上述操作后旧 token 才失效。

#### 2.2.3 强制改密在服务端生效

`get_current_user` 在 `must_change_password=1` 时，仅允许访问：

- `/api/auth/change-password`
- `/api/auth/logout`
- `/api/auth/deactivate`
- `/api/v1/profile` 及其子路径
- `/api/v1/invites`（公开邀请链接的预览/接受，避免改密前连课程信息都看不到）

其他业务接口返回 403：
> 请先修改初始密码后再使用其他功能

这样即使绕过前端路由守卫直接调用 API，也无法在未改密前使用业务功能。

#### 2.2.4 改密后返回新 token

`POST /api/auth/change-password` 成功响应新增 `access_token`：

```json
{
  "user_id": 5,
  "access_token": "...",
  "token_type": "bearer"
}
```

原因：改密会递增 `token_version`，旧 token 立即失效。若不返回新 token，用户会在改密成功后的下一个请求被 401 踢回登录页。前端 `ChangePasswordView` 已同步写回新 token。

#### 2.2.5 登录失败限流

- 按「用户名 + 直连 IP」计数，10 分钟内失败 8 次后返回 HTTP 429：
  > 登录失败次数过多，请 10 分钟后再试
- 成功登录后清零。
- 限流表上限 4,096 个桶，超出时淘汰最早插入的桶，避免被随机用户名撑爆内存。
- 说明：进程内实现，单 worker 足够；多 worker 部署需换 Redis 等共享存储。

#### 2.2.6 管理员校验简化

`require_admin` 不再重复查库：`get_current_user` 已经完成「存在 + 启用 + 角色 + token 版本」四项校验，`require_admin` 只判断数据库返回的角色。管理员端点行为不变。

### 2.3 练习接口补齐课程级权限

### 2.6 启动健壮性、健康检查与日志

**文件**：`backend/app/main.py`、`backend/app/core/database.py`、`backend/app/core/metrics.py`

1. **Neo4j 约束/索引初始化**
   - `lifespan` 中调用 `db.init_schema()`。
   - `init_schema()` 返回 `True/False`；图库不可达时跳过剩余语句并返回 `False`，服务仍可启动，但日志明确告警。
2. **Neo4j 熔断范围收窄**
   - 只有 `ServiceUnavailable` / `SessionExpired` 才打开 30 秒熔断。
   - Cypher 语法错、约束冲突、权限不足不再导致全站图查询停摆。
3. **健康检查（存活 / 依赖分离）**
   - `GET /health`（liveness）：只返回 `{"status":"ok"}`，不查数据库，确保登录页 3 秒超时内必定有响应。
   - `GET /health/deps`（readiness）：返回依赖状态，允许较慢：
     ```json
     {
       "status": "ok | degraded",
       "dependencies": { "sqlite": "ok", "neo4j": "ok | error" }
     }
     ```
   - 背景：Neo4j 不可达时驱动连接超时为 2 秒（IPv6/IPv4 各一次），如果 `/health` 同步查图库，单次请求会到 4 秒，超过前端 3 秒超时，导致登录页误报"服务暂时不可用"。因此把依赖检查拆到 `/health/deps`。
4. **日志**
   - 启动时按 `LOG_LEVEL` 配置基础日志格式。
   - 未捕获异常统一记录完整堆栈，对外只返回固定文案。
5. **统一错误响应**
   - 新增 `RequestValidationError` 处理器：把 FastAPI 默认的英文 422 数组转成一条中文消息，如：
     > 参数校验失败：「password」缺少必填字段
   - 新增兜底 `Exception` 处理器：返回 `{"code":5000,"message":"服务器内部错误，请稍后重试"}`，避免 FastAPI 默认纯文本。
6. **监控指标 key 降基数**
   - 中间件改用路由模板（如 `/api/v1/documents/{doc_id}`）而不是原始 URL。
   - `metrics` 增加 200 个路径桶上限，超出归入 `__other__`。

### 2.7 上传限制前置

**文件**：`backend/app/api/documents.py`、`backend/app/api/profile.py`、`backend/app/core/config.py`

- 单文件上传：读取前检查 `UploadFile.size`，超过 50MB 直接拒绝。
- 批量上传：
  - 单次最多 `MAX_BATCH_FILES=20` 个文件；
  - 单个文件超过 50MB 直接拒绝，并指出文件名。
- 头像上传：读取前检查 2MB 限制。
- 说明：这仍不是完整的流式解析（Starlette 已先把请求体 spool 到临时文件/内存），但避免了「先全量读入再判大小」的最坏路径。

### 2.8 错误信息不再泄露内部细节

**文件**：`backend/app/services/qa_service.py`、`backend/app/api/graph.py`

- 问答生成失败：对外固定返回「抱歉，问答服务暂时不可用，请稍后重试。」，完整异常写日志。
- 图谱查询失败：对外固定返回「图谱查询失败，请稍后重试」，完整异常写日志。

### 2.9 数据库变更

**文件**：`backend/app/core/sql_database.py`

新增列：

```sql
ALTER TABLE t_user ADD COLUMN token_version INTEGER NOT NULL DEFAULT 0;
```

- 新库由 `_SCHEMA_SQL` 直接建出该列。
- 旧库由 `_migrate_admin_user_columns()` 幂等补齐。
- `_migrate_admin_role()` 重建 `t_user` 时也保留该列。
- 迁移自动执行，无需手工操作；`token_version` 默认 0，旧 token 兼容。

## 八、配置与回滚说明

### 8.1 首次升级前请确认

1. `backend/.env` 已设置：
   - `SECRET_KEY`（≥32 字符）
   - `NEO4J_PASSWORD`
   - 如需跨域访问，设置 `CORS_ORIGINS`
2. 数据库会在启动时自动增加 `token_version` 列，无需手工迁移。
3. 已经登录的用户在升级后不会被强制下线（旧 token 的 `ver` 按 0 处理，历史用户版本也是 0）。

### 8.2 如需恢复旧行为

| 需求 | 配置/操作 |
|---|---|
| 允许教师自助注册 | `.env` 设 `ALLOW_TEACHER_SELF_REGISTER=true` |
| 登录页显示演示账号（生产构建） | 构建时设 `VITE_SHOW_DEMO_ACCOUNTS=1` |
| 允许任意来源跨域 | `.env` 设 `CORS_ORIGINS=*`（不推荐；此时 `allow_credentials=False`） |
| 回滚代码 | 还原对应文件即可；`token_version` 列可保留，不影响旧代码（旧代码不读取该列） |

### 8.3 注意事项

- 修改 `SECRET_KEY` 会使所有已签发 token 失效，用户需重新登录。
- 管理员重置密码、禁用账号、修改角色后，目标用户的现有 token 会立即失效，这是预期行为。
- 教师账号现在需要管理员在「用户管理」中创建/提升；演示环境可使用已有的 `demo_teacher` 账号，或临时开启 `ALLOW_TEACHER_SELF_REGISTER`。
